- 每个被测子包在 `tests/` 下建立同名子目录，并以 `test_<feature>.py` 命名单个用例文件，保持与源码包的一一对应关系。
- 需要文件系统隔离的套件在自身 `conftest.py` 中定义 `autouse` 或显式 fixture，通过 `monkeypatch.setattr(deeptutor.multi_user.paths, ...)` 将 `PROJECT_ROOT`、`ADMIN_WORKSPACE_ROOT`、`USERS_ROOT`、`SYSTEM_ROOT` 重定向到 `tmp_path`，并清空 `_path_services` 缓存。
- 对外部 LLM/HTTP 依赖统一使用 `unittest.mock.MagicMock` 构造配置对象（如 `fake_llm_config`），而非发起真实请求。
- 对多用户场景使用 `as_user(uid, role=...)` 上下文管理器配合 `CurrentUser` 的 contextvar 切换身份，避免在 HTTP 层之外绕过权限检查。
- JSON 响应等外部契约数据以 fixtures 目录中的静态文件（如 `models-response.json`）提供，便于断言序列化/反序列化行为。
- 针对能力（capability）的测试通过继承 `BaseCapability` 并声明 `CapabilityManifest` 来构造最小可运行的 stub capability，用于注入流式事件。
