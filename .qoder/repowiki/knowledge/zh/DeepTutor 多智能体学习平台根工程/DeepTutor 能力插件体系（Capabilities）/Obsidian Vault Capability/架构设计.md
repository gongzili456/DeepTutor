模块按职责分层组织：`capability.py` 实现 `KnowledgeCapability` 接口（`is_active`、`owned_kbs`、`system_block`、`augment_kwargs`），决定何时激活并注入系统提示；`binding.py` 从 `context.knowledge_bases` 解析出首个 `type == obsidian` 的知识库引用，缓存到 `context.metadata` 供同轮复用；`tools.py` 定义九个 `BaseTool` 子类（search/read/list/backlinks/links/tags/create_note/append/set_property），统一继承 `_ObsidianTool` 以完成 vault root 校验与错误归一化；`vault.py` 是纯函数层，仅依赖 `pathlib` 和 `yaml` 实现对 `.md` 文件的前置 YAML frontmatter 解析、wikilink 正则提取、标签统计及只增不改的写操作。依赖方向单向：capability → binding → tools → vault，且通过 `OBSIDIAN_TOOL_NAMES` / `OBSIDIAN_TOOL_TYPES` 两个单一定义源保证挂载策略与注册表一致。安全边界由 capability 的 `augment_kwargs` 在服务端注入不可伪造的 `_vault_path`，并由 `vault._safe_join` 拒绝逃逸路径。
