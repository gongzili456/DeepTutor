- 所有可变状态以 dataclass 建模（`CronSchedule`、`CronOwner`、`CronJobState`、`CronRunRecord`、`CronJob`），并通过 `from_dict` / `asdict` 实现 JSON 序列化与反序列化。
- 对外部依赖（`croniter`、`zoneinfo`、各业务子系统）采用函数内局部 import，避免模块启动时的强耦合与循环导入。
- 作业生命周期统一通过 `next_run_at_ms` 字段驱动：调度器只检查该字段是否 ≤ now，运行后重新计算下一次时间或移除一次性作业。
- 持久化采用原子写入模式：先写 `.tmp` 文件再 `replace` 目标路径，并在读取失败时将损坏文件重命名为带时间戳的 `.corrupt-*` 副本。
- 错误处理统一返回 `(status, error)` 元组（`ok`/`error`/`skipped`），由 `CronService._run_job` 捕获异常并记录到 `run_history`，最多保留最近 10 条。
- 通过 `CronOwner.key`（`chat:{user_id}` 或 `partner:{partner_id}`）作为所有者维度进行作业过滤与批量删除，使同一用户/伙伴的作业可被统一清理。
