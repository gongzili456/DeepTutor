模块以 `modes/` 下的四种模式（update/audit/dedup/merge）为核心入口，统一通过根包 `__init__.py` 暴露 `run_update`、`run_audit`、`run_dedup`、`run_merge` 以及兼容旧接口的 `consolidate_l2/l3` shim。

- 运行时基础设施集中在 `modes/_runtime.py`：提供 prompt YAML 加载与缓存（按 en/zh）、SSE 事件发射 `emit`、LLM 调用封装 `call_llm`（流式优先，失败回退到非流式）、文档的原子写入 `write_doc_atomic` 与带 undo 记录的 `write_doc_checkpoint`。
- 每种模式文件（`update.py`、`audit.py`、`dedup.py`、`merge.py`）只关注算法流程，依赖 `_runtime` 完成 I/O；L2/L3 update 共享同一套 chunk→LLM→parse facts→validate refs→append 流水线，差异仅在输入来源（L1 snapshot vs L2 entries）和引用池构造。
- 纯函数工具层独立于 I/O：`chunker.py` 实现基于段落/句号的边界扩展分块；`meta.py` 维护每文档的 `*.meta.json`（记录上次 seen ids），用 temp+rename 原子写；`references.py` 做 ref pool 校验与 raw-trace 标注；`line_doc.py` 提供行号视图与 edit 操作；`guards.py` 过滤禁用短语；`parse.py` 解析 legacy ops 数组。
- 提示词按语言与模式拆分为 `prompts/{en,zh}/*.yaml`，由 `_runtime.load_prompt` 按 `(lang, name)` 键缓存。
- 依赖方向单向：modes → _runtime → (llm/document/settings)，并反向通过延迟 import 避免循环（如 update 末尾按需导入 dedup/merge）。
