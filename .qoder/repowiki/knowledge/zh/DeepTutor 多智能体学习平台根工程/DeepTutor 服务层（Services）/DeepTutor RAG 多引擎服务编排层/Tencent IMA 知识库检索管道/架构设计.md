模块按职责拆分为四个文件：`pipeline.py` 暴露 `ImaPipeline` 类实现上层 RAG 管道契约（`search`/`initialize`/`add_documents`/`delete`），其中仅检索路径有实际逻辑，索引相关方法明确拒绝或无操作；`config.py` 定义不可变 `ImaConfig` dataclass、`SUPPORTED_MODES=()` 以及从 `kb_config.json` 条目解析配置的 `config_from_entry`，缺失字段时抛出 `ImaNotConfiguredError`；`client.py` 封装对 `https://ima.qq.com/openapi/wiki/v1/*` 的异步 HTTP 调用（`search_knowledge` 与 `get_knowledge_base`），统一处理 `{code,msg,data}` 信封并按业务码区分认证错误与限流错误，搜索通过 cursor 分页并限制最多 3 页；`probe.py` 提供连接前健康检查 `probe_knowledge_base`，调用一次 `get_knowledge_base` 同时验证凭据与 KB ID，返回非抛异常的 `ImaProbe` 数据类。依赖方向单向：`pipeline → config + client`，`probe → client + config`，`__init__.py` 仅重导出 `ImaPipeline`。配置通过注入 `client_factory` 和 `httpx.AsyncBaseTransport` 在测试中替换，避免真实网络访问。
