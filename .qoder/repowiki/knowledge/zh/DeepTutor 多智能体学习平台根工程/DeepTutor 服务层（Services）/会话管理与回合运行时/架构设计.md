模块以 `protocol.py` 中的 `SessionStoreProtocol`（`@runtime_checkable Protocol`）定义统一异步接口，作为所有后端的契约边界；`sqlite_store.py` 的 `SQLiteSessionStore` 和 `pocketbase_store.py` 的 `PocketBaseSessionStore` 分别实现该协议，由 `__init__.py` 的 `get_session_store()` 根据 `is_pocketbase_enabled()` 在启动时动态选择后端。

上层通过两类抽象使用存储：
- 基于 JSON 文件的旧式 `BaseSessionManager`（`base_session_manager.py`），子类如 `UnifiedSessionManager`（`unified_session_manager.py`）只需实现 `_get_session_id_prefix`、`_create_session_data`、`_get_session_summary` 等钩子，将不同能力（chat/deep_solve/…）的会话写入各自模块目录下的 JSON 文件。
- 基于 `SessionStoreProtocol` 的新式 `TurnRuntimeManager`（`turn_runtime.py`），负责编排一次 turn 的完整生命周期：校验 capability config、解析 persona/llm_selection/tools、恢复孤儿 running turn、创建 turn 并后台 `asyncio.create_task(_run_turn)` 执行，同时维护进程内 `_executions` 与 `_reply_queues` 以支持 `ask_user` 暂停/恢复、`cancel_turn`、`regenerate_last_turn` 以及按 `after_seq` 增量订阅 `turn_events`。

数据模型集中在 `sqlite_store.py` 的 DDL 中：`sessions`、`messages`（含 `parent_message_id` 实现编辑分支）、`turns`、`turn_events`、`notebook_entries`、`notebook_categories`，并通过 `_initialize` 内的 `ALTER TABLE` 迁移保证向后兼容；导入会话通过 `make_imported_session_id` 生成带 `imported_<source>_` 前缀的确定性 ID 以实现幂等重导入。

依赖方向单向向下：`TurnRuntimeManager` → `SessionStoreProtocol` → 具体 store；`BaseSessionManager` 仅依赖 `path_service` 定位 JSON 文件，不感知 store 协议。
