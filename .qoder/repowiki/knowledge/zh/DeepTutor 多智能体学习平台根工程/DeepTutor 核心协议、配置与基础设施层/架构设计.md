本模块按职责划分为五个并列子包，构成上层编排器、工具实现和外部插件共同依赖的基础设施：
- `core/`：定义跨层契约——`tool_protocol.py` 中的 `BaseTool`/`ToolDefinition`/`ToolResult` 是 Level 1 工具接口；`capability_protocol.py` 中的 `BaseCapability`/`CapabilityManifest` 是 Level 2 多阶段能力接口；`context.py` 的 `UnifiedContext`+`Attachment` 作为单次用户请求贯穿所有调用的数据载体；`stream.py`+`stream_bus.py` 提供基于 `asyncio.Queue` 的 fan-out 流式通道（含 `stage` 上下文管理器、`wait_for_input` 双向交互）；`trace.py` 提供调用链 ID 生成与合并；`agentic/` 子目录封装 LLM 客户端循环、工具参数守卫与标签化步骤。
- `config/`：基于 Pydantic + `pydantic_settings` 的声明式配置体系，`schema.py` 定义 `AppConfig`/`LLMConfig`/`PathsConfig` 等模型，`settings.py` 通过 `env_prefix='LLM_'`、`env_nested_delimiter='__'` 将环境变量映射为 `Settings` 单例，`accessors.py`/`defaults.py`/`constants.py` 提供路径与常量访问。
- `logging/`：以 stdlib `logging` 为主干，`configure.py` 的 `configure_logging(force)` 一次性安装控制台与 `RotatingFileHandler`（输出 `data/user/logs/deeptutor.jsonl`），并通过 `loguru_bridge` 桥接 Loguru；`formatters.py` 提供 `ConsoleFormatter`/`JsonlFormatter`；`context.py` 暴露 `bind_log_context`/`current_log_context` 用于结构化字段注入；`stats/` 统计 LLM 调用成本；`adapters/llamaindex.py` 适配第三方库日志。
- `events/`：独立的进程级异步事件总线 `EventBus`（单例 + `asyncio.Queue` 后台处理器），支持 `subscribe/publish/start/flush/stop/reset`，事件类型由 `EventType` 枚举限定，用于解耦完成态通知。
- `i18n/`：纯静态本地化字典，`metadata_i18n.py` 维护内置 capability/tool 的 en/zh 描述，`status_i18n.py` 提供状态字符串查找，供 UI 与能力管线按 `language` 字段渲染。
依赖方向自下而上：`core` 不依赖其他子包；`config` 仅依赖 Pydantic；`logging` 被其余子包通过标准 `logging` 模块间接使用；`events` 与 `i18n` 独立无内部依赖；上层编排器消费这些子包提供的协议与基础设施。
