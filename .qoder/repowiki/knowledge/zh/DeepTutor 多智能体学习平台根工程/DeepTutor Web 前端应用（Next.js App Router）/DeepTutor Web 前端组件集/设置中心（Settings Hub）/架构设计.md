模块以 `SettingsContext.tsx` 中的 `SettingsProvider` 为单一状态源，维护 `Catalog`（llm/embedding/search/tts/stt/imagegen/videogen 七类服务及其 profile/model）、UI 偏好（theme/language/response_language/code block 主题等）、系统状态、诊断结果与引导流程；所有子页面通过 `useSettings()` 消费并调用 `mutateCatalog`/`update*` 修改草稿，再由 `saveCatalog`/`applyCatalog` 批量提交到 `/api/v1/settings`。

- 入口与布局：`SettingsMain.tsx` 根据路由区分 hub（`/settings`）与 leaf 页，leaf 页渲染 `SettingsBreadcrumb`、`SettingsToolbar`（含 Save Draft / Apply 按钮）和滚动容器；`SettingsHub.tsx` 作为首页网格展示各分类卡片，并聚合 `SettingsStatusPanel`。
- 领域数据层：`SettingsContext.tsx` 定义 `ServiceName`、`CatalogProfile`、`CatalogModel`、`SystemStatus`、`DiagnosticsResult` 等核心类型，并提供 `getActiveProfile`/`getActiveModel`/`serviceReadiness`/`currentDiagnosticsResult` 等查询辅助函数。
- 专用编辑器：`ServiceConfigEditor.tsx`、`SubagentSettingsEditor.tsx`、`MinerUEngineSettings.tsx`、`CodexOAuthCard.tsx` 按服务类型渲染差异化表单；`DimensionField.tsx`、`ThemePreviewCard.tsx`、`Toggle.tsx` 为通用控件。
- 共享 UI 与常量：`shared.tsx` 暴露 `SettingRow`/`SettingSection`/`SettingsPageHeader` 以及输入样式、搜索 provider 白名单、标签排版等；`codex-profile.ts` 标记 Codex OAuth 管理的只读 profile；`search-providers.ts` 映射每个搜索 provider 的字段需求（apiKey/baseUrl），与后端 `provider_runtime.py` 保持同步。
- 依赖方向：叶子组件 → `SettingsContext` → 外部 `@/lib/api`、`@/context/app-shell-storage`、`@/lib/theme`、`@/lib/llm-options`；不反向被业务模块引用，仅由 settings 路由树使用。
