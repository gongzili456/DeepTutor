模块以 `service.py` 中的 `SandboxService` 作为唯一对外门面，封装后端选择、健康探测缓存、每用户并发/速率配额以及 exec 工具访问策略检查；调用方通过 `get_sandbox_service()` 获取单例。
- 配置与后端选择集中在 `config.py`：按环境变量优先级依次尝试 runner sidecar（`DEEPTUTOR_SANDBOX_RUNNER_URL`）、Linux 上的 `bwrap`、或需显式开启的受限子进程，最终由 `build_backend` 返回具体实现或 None。
- `backends.py` 定义抽象基类 `SandboxBackend`（暴露 `exec`/`health` 与 `level: IsolationLevel`），并提供三种实现：`RunnerSidecarBackend`（HTTP + httpx 调用 `/exec`）、`BwrapBackend`（通过 `bwrap --unshare-all` 建立 mount namespace）、`RestrictedSubprocessBackend`（仅清理 env/cwd 的 APPLICATION 级隔离）。
- `spec.py` 声明无第三方依赖的数据契约（`IsolationLevel`、`ExecRequest`、`ExecResult`、`ResourceLimits`、`Mount`），被 service/backends/quota 共同引用，保证调用方与后端解耦。
- `quota.py` 基于 asyncio.Semaphore + 滑动窗口 deque 实现 per-user 并发与每分钟速率限制，失败时抛出 `QuotaExceeded`。
- `artifacts.py` 扫描工作区输出并生成可通过 `/api/outputs` 公开下载的文件清单，与执行路径解耦。
- `runner/server.py` 是独立部署的侧车进程（标准库 `http.server`，无第三方依赖），监听 `/health` 与 `/exec`，使用 `resource.setrlimit` 对子进程施加内存/CPU/文件描述符上限，并通过白名单校验 `workdir` 仅限共享卷目录。
- 依赖方向：service → backends/config/spec/quota/artifacts；runner/server 仅被 backends 通过 HTTP 调用，不反向依赖主应用。
