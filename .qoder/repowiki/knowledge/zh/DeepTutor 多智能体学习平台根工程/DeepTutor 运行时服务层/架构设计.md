本模块以 `services/__init__.py` 作为懒加载门面（`__getattr__` 按需 import llm/embedding/rag/prompt/search/session/config），避免循环导入并延迟重型依赖；跨子模块共享的横切契约集中在根级：`config` 提供 YAML/JSON 运行时设置与模型目录的单例读取；`auth.py` 提供 JWT/PocketBase 双模式用户认证；`path_service.py` 管理数据目录；`provider_registry.py` 集中声明 `ProviderSpec` 元数据（keywords/env_key/api_base/detect_by_*），被 llm、model_selection、codex_auth、subagent 等模块共同用于按 model name / api_key / api_base 自动路由到具体后端；`pocketbase_client.py` 提供 PocketBase 集成客户端。

每个子包遵循「门面 Service/Client + adapters/providers 子目录」的可插拔结构：新增后端只需在适配器下实现并注册，无需修改门面。典型调用链路自上而下为：上层 agent 或 CLI → session.turn_runtime → memory/RAG/smart_retriever → embedding/search → llm.client → sandbox 执行工具 → cron 定时投递，所有环节共享同一份 config 单例与 auth 上下文，并通过 Python 包级导入保持同进程低延迟。各子模块之间不直接互相依赖业务逻辑，而是通过 config、auth、path_service 和 provider_registry 这四个横切契约进行解耦协作。
