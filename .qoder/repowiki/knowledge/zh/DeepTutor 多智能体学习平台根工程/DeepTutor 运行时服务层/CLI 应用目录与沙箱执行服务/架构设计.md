模块按严格自底向上的依赖分层组织（见 `__init__.py` 注释）：最内层 `models.py` 定义不可变数据类（`CliAppEntry`、`InstallPlan`、`InstallKind`、`AppTrust`、`AppRuntime`），并仅通过白名单解析第三方注册表的 `install_cmd`，绝不直接执行；`catalog.py` 加载本地 vendored 快照并提供搜索/分类能力；`paths.py` 集中所有磁盘布局常量（app root、runtime venv、bin、日志路径）；`state.py` 持久化“已安装”和“账户禁用”集合；`installer.py` 是管理员入口，基于 `InstallPlan` 顺序执行 `python -m venv` + `pip install` 或 `npm install --prefix`，失败时回滚旧环境并写日志；`runner.py` 通过 `services.sandbox` 的 `ExecRequest.of_argv` 以参数向量方式运行已安装可执行文件，注入只读 app_root 挂载与受限环境变量；`provider.py` 将每个已授权应用包装为 `BaseTool`（名称 `cli_<id>`），实现渐进式披露——工具描述先来自目录摘要，再动态读取已安装包内的 `SKILL.md`/`AGENT.md` 并做 sanitize。依赖方向单向向内，顶层仅重新导出 `models` 与 `catalog` 的公共 API，避免引入 sandbox/tool registry 等重依赖。
