模块按职责拆分为四个文件：`pipeline.py` 实现 `LightRagServerPipeline`，遵循上层 `RAGPipeline` 契约，只实现 `search`（其余索引/删除方法显式拒绝或空操作），并通过注入的 `client_factory` 在测试中替换 HTTP 客户端；`client.py` 封装对 LightRAG 服务器 REST API 的异步调用（`POST /query?only_need_context=True`、`GET /auth-status`、`GET /documents/pipeline_status`），使用 httpx 并支持可插拔 transport；`config.py` 定义 frozen dataclass `LightRagServerConfig` 与 per-KB 配置解析函数 `config_from_entry`，将 `kb_config.json` 中的 `server_url`/`api_key` 映射为类型化配置；`probe.py` 提供 `probe_server`，通过两次探测（无鉴权 `/auth-status` + 可选鉴权的 `/documents/pipeline_status`）在连接 KB 时验证可达性与 API key。依赖方向单向：`pipeline → client/config`，`probe → client/config`，`__init__.py` 仅暴露 `LightRagServerPipeline` 作为对外入口。
