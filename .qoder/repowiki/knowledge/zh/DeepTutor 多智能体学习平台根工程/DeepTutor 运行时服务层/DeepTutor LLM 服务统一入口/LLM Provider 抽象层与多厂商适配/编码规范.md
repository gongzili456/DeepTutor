- 每个具体 provider 都继承 `LLMProvider` 并实现 `chat` 与 `get_default_model` 两个抽象方法，其余重试、流式包装由基类提供。
- 对外统一返回 `LLMResponse` dataclass，内部错误以 `finish_reason="error"` 的响应形式上报，而非抛出异常。
- 对第三方 SDK 的错误进行统一捕获并转为 `LLMResponse(content=..., finish_reason="error")`，便于上层重试逻辑判断是否为瞬态错误。
- 工具调用 ID 采用复合键（如 `call_id|item_id`），在 Responses 编解码中通过 `split_tool_call_id` 拆分/拼接以维持跨端一致性。
- SSE 流解析统一通过 `iter_sse` / `consume_sdk_stream` 等工具函数处理，按 `response.output_item.added`、`response.output_text.delta`、`response.function_call_arguments.done` 等事件类型分派。
- provider 类通过 `TYPE_CHECKING` 块引入重型类型或可选依赖，并在运行时用 `import_module` 懒加载，避免冷启动开销。
