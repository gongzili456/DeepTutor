模块以 `factory.py` 的 `complete/stream/fetch_models` 作为对外主入口，按固定链路编排：先由 `_resolve_call_config` 合并调用参数与全局 `LLMConfig`，再通过 `provider_registry.PROVIDERS` 根据 binding/model/base_url/gateway 解析出 provider spec；随后 `provider_factory.get_runtime_provider` 基于 spec 的 backend 字段按需 import 并实例化 `provider_core` 下的具体实现（OpenAICompat/AzureOpenAI/Anthropic/OpenAICodex/GitHubCopilot），并以事件循环为键维护最多 2 个连接池化的 SDK 客户端；请求经 `executors` 的重试/熔断/流量控制管线后落到底层 provider，错误统一经 `error_mapping.map_error` 转为本模块异常。`client.py` 暴露遗留的 `LLMClient` 类，仅做参数适配并委托给 factory；`cloud_provider`/`local_provider` 通过 `__getattr__` 懒加载以避免重依赖启动开销；`capabilities.py`、`config.py`、`multimodal.py`、`reasoning_params.py` 等横切文件被各子模块共享，构成跨 provider_core、providers 与核心运行时的统一契约。
