- 对外 API 统一为 `factory.complete` / `factory.stream` 两个 async 函数，类式 `LLMClient` 仅作为遗留包装器存在。
- 所有底层 SDK 仅在需要时通过局部 import 引入，避免在模块加载阶段引入重型依赖。
- Provider 选择遵循“显式 binding → gateway → model 匹配 → base_url 本地检测 → 默认 openai”的降级顺序，并在 `provider_factory` 中以 (loop, provider_name, mode, model, api_key 指纹, effective_url, api_version, headers, temperature, max_tokens, reasoning_effort) 为键缓存实例。
- 错误处理统一经由 `error_mapping.map_error` 转换为 `exceptions.py` 中的领域异常，再向上抛出。
- 能力探测（vision/response_format/tools/system_in_messages）集中通过 `capabilities.py` 的 `supports_*` 函数判断，而非在各 provider 中重复实现。
- 配置合并采用“当前 LLMConfig 为主、调用参数为部分覆盖”的策略，保留 profile-only 字段如 extra_headers 与 reasoning_effort。
