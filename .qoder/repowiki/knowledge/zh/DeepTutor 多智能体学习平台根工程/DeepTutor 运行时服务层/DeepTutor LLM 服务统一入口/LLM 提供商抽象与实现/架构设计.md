模块以 `base_provider.py` 中的 `BaseLLMProvider` 抽象类为核心，所有具体提供商均继承该类并实现 `complete` 与 `stream` 两个接口；基类封装了跨提供商共用的执行管线：电路断路器检查（`_check_circuit_breaker`）、基于 `TrafficController` 的并发与速率限制、统一异常映射（`map_error`）与失败计数上报、以及基于 `tenacity.AsyncRetrying` 的可配置指数退避重试（对限流/超时/5xx 自动重试）。具体实现按文件划分：`open_ai.py` 通过 `openai.AsyncOpenAI`/`AsyncAzureOpenAI` 调用 Chat Completions API；`anthropic.py` 通过 `anthropic.AsyncAnthropic` 调用 Messages API，并使用 `_sanitize_kwargs` 过滤掉仅适用于 OpenAI 的 kwarg；`routing.py` 中的 `RoutingProvider` 根据 `base_url` 是否命中本地服务器动态委派给 `cloud_provider.complete/stream` 或 `local_provider`，并在可选时接入 `deeptutor.services.llm.cache` 完成结果缓存。所有提供商通过 `@register_provider(...)` 装饰器在 `registry` 中注册，由上层工厂按需实例化。依赖方向单向向下：各 provider → base_provider → 共享的 config/exceptions/types/traffic_control/network/cost 等上层模块，本模块不反向依赖业务层。
