包内按职责分层，依赖方向自下而上：
- `allowlist.py` 定义不可变 `Allowlist` 类型，显式表达「受限集合」与「unrestricted」两种状态，并提供 `narrow`/`widen` 等幂等操作，是上层所有策略的基础。
- `scope.py` 用 frozen dataclass 描述单轮决策输入 `ToolScope`（owner_id、workspace_mcp、is_partner、caller_whitelist、exclusive_capability），刻意不抽象成接口，因为 MCP 与 CLI 的授权键不同。
- `authorize.py` 按 provider kind 拆分授权函数（当前仅 `authorize_mcp_tools`），复用 Allowlist 但保留 per-kind 分支，避免把两类策略合并成一个模糊集合。
- `text.py` 提供第三方文本清洗器（`sanitize_provider_text` / `sanitize_provider_document`），对 manifest 行做扁平化+长度截断，对文档做控制字符过滤+空白折叠。
- `view.py` 是唯一向上依赖 registry 的入口，组合上述模块并调用 `deeptutor.services.mcp` 与 `cli_apps.provider`，产出 `ProviderToolView`；它通过 try/except 包裹整个异步流程，保证构建失败时降级为空视图，不中断 turn。
- `__init__.py` 仅 re-export 无环依赖的四个子模块 API，明确禁止在包级 re-export `view`，以避免与 `deferred_tools` 形成循环导入。
