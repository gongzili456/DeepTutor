模块由四个职责正交的子文件组成，通过 `__init__.py` 的 `__getattr__` + `_EXPORTS` 表实现按需懒导入，避免启动时加载重型依赖。

- `capability_registry.py`：面向旧版 turn capability 的兼容层 `CapabilityRegistry`，内部委托 `CapabilityCatalog`；支持三种注册入口——显式 `register()`、`load_builtins()`（来自 `BUILTIN_CAPABILITY_SPECS`）、`load_plugins()`（先走 `deeptutor.extensions` entry point，再回退到已弃用的 `deeptutor.plugins` 组），并通过 `contribution_enabled` 做贡献开关过滤；`get_capability_registry()` 返回带单例缓存的默认实例。
- `tool_registry.py`：进程全局的 `ToolRegistry`，维护 `BaseTool` 字典，支持别名解析（`TOOL_ALIASES`）、builtin 惰性创建（`_load_builtin` 从 `BUILTIN_TOOL_SPEC_BY_NAME` 构造）、插件发现（entry point `deeptutor.tools` + `PluginRegistry().load_enabled_tools`）；`get_tool_registry()` 在插件状态目录 mtime/size 变化时重建实例并保留共享 MCP tool。
- `scoped_registry.py`：`ScopedToolRegistry` 作为只读代理，叠加 per-turn overlay（用户/租户专属工具）与 process registry base，并在 `execute()` 处通过 `Allowlist` 对 `deferred` provider 工具做授权拦截，解决多租户同名冲突与运行时鉴权问题。
- `deferred_tools.py`：处理标记 `deferred=True` 的工具（默认全部 MCP 工具）的渐进披露——`render_deferred_tools_manifest` 生成系统提示中的精简清单并按 provider 分组，`DeferredToolLoader` 在 `load_tools` 调用时把完整 schema 追加进本轮 `tool_schemas`，并把已加载名称持久化到 MCP session state。

依赖方向单向向外：本模块依赖 `core.tool_protocol` / `core.capability_protocol`、`plugins`、`modules.catalog`、`runtime.providers` 等上层子系统，但被这些子系统反向引用以获取工具/能力列表。
