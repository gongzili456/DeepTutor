模块按职责拆分为五个内聚子文件：
- `contracts.py` 定义跨组件的数据契约（`CodexCredentials`、`CodexToken`、`CodexModel`、`CatalogSnapshot`、`TokenClaims`）以及统一的 `CodexAuthError` 异常，所有外部输入在 `from_dict` / `decode_codex_jwt` 处做严格类型校验。
- `constants.py` 集中 OAuth 端点、回调路径、端口、超时等常量。
- `oauth.py` 实现 PKCE（S256）、授权 URL 构建、loopback HTTP 回调监听（基于 `asyncio.start_server` 绑定 `127.0.0.1`/`::1`），是纯协议层，不依赖服务状态。
- `storage.py` 通过进程级文件锁（Windows `msvcrt.locking` / POSIX `fcntl.flock`）+ 原子写入（`tempfile.mkstemp` + `os.replace`）维护 `private/openai-codex/` 下的凭据、state 与模型缓存，并以 generation 号防止并发覆盖；同时拒绝符号链接与重解析点以防御越权读写。
- `catalog.py`、`client_version.py` 负责从 OpenAI 拉取并缓存模型目录。
- `service.py` 是编排核心 `CodexOAuthService`，组合上述组件，管理异步登录操作（`_LoginOperation` 状态机）、令牌刷新、`reconcile_codex_catalog_update`/`sync_codex_catalog`/`remove_codex_catalog` 三个 catalog 变更函数，并通过 `MANAGED_BY="openai_codex_oauth"` 标记受管 profile，保证 provider 元数据权威且可被用户手动编辑后安全合并。
依赖方向单向：`service → oauth/storage/catalog/client_version → contracts/constants`，对外仅由 `__init__.py` 暴露 `get_codex_oauth_service`、`reconcile_codex_catalog_update` 及数据类。
