- 所有面向外部的结构化数据（credentials、model、snapshot、token claims）都提供 `to_dict` / `from_dict` 并在反序列化时抛出 `CodexAuthError`，将格式错误统一映射为带 code/http_status 的错误码。
- 可变状态变更通过 `asyncio.Lock`（`_operation_lock`、`_refresh_lock`、`_catalog_sync_lock`、`_inference_lock`）串行化，避免并发登录、刷新、目录同步与推理之间的竞态。
- 对外的业务错误统一用 `CodexAuthError(code, public_message, http_status)` 表达，HTTP 状态码直接决定上层响应码，字符串形式即对用户可见的消息。
- 受管 LLM profile 通过 `managed_by="openai_codex_oauth"` 标记并由 `_managed_profile_indexes` 定位，所有 catalog 写操作先过滤掉该标记再插入，确保 provider 元数据始终权威。
- 凭据与 state 文件采用 atomic write（临时文件 + `os.replace`）+ 进程级文件锁，并以 `generation` 版本号检测并发修改，旧请求不会覆盖新会话。
