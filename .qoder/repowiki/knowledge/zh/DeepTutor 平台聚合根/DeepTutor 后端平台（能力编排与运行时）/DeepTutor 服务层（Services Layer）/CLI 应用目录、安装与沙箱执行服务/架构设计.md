模块内部遵循 `__init__.py` 中声明的单向依赖链，由内向外分层：
- `models.py`（最内层）：定义 `CliAppEntry`、`InstallPlan`、`InstallKind`、`AppTrust`、`AppRuntime` 等不可变数据类，并实现从上游 registry 的 `install_cmd` 解析为安全 argv 的白名单解析器，拒绝 shell 管道/重定向；对路径型字段用 `APP_ID_RE` / `ENTRY_POINT_RE` 校验。
- `catalog.py`：加载 `vendor/catalog.json` 快照（进程级 `lru_cache`），将行映射为 `CliAppEntry`，并提供分页搜索、分类统计和 `catalog_pin()`。
- `paths.py` + `state.py`：约定安装根目录、各 runtime 子目录、ABI 时间戳，以及持久化的已安装清单与每账户禁用列表。
- `installer.py`：管理员专用，按 `InstallPlan.kind` 生成 venv/npm 安装步骤，使用 `.old` 备份做原子回滚，并通过 `asyncio.Lock` 串行化同 app 并发安装。
- `runner.py`：把 `InstalledApp` 包装成 `ExecRequest.of_argv`，仅把自身 `bin` 目录注入 PATH，限制超时与输出长度，交由 `deeptutor.services.sandbox` 执行。
- `provider.py`：对外暴露 `BaseTool`（`cli_<app_id>`），实现渐进式披露——manifest 只展示目录摘要，`load_tools` 时才读取已安装包内的 `SKILL.md`/`AGENT.md` 作为 schema 描述；`authorized_apps` 集中处理 installed/granted/enabled/exec_allowed 三层授权策略。

依赖方向严格自下而上，顶层 `__init__.py` 仅重新导出模型与 catalog API，避免把 sandbox/tool-registry 拉入每个消费者。
