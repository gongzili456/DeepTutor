模块以 `manager.py` 中的 `MCPConnectionManager` 为进程级单例入口，按 `(owner, server_name)` 键维护 `_ServerConnection`，每个服务器由一个独立的 asyncio task 持有 `AsyncExitStack`，在相同任务内完成 connect → initialize → list_tools → wait(shutdown) → exit，从而满足 MCP SDK anyio cancel scope 的任务绑定约束。

内部分层清晰：
- 配置层：`config.py` 定义 Pydantic 的 `MCPServerConfig`/`MCPConfig`，持久化到管理员工作区的 `mcp.json`；`user_config.py` 复用同一模型但加载自 `data/system/user-mcp/<owner>.json`，并拒绝 stdio 传输、限制每账户 ≤8 个服务器。
- 运行时层：`manager.py` 负责连接池、重试退避、连接丢失检测、工具适配器注册到全局 `ToolRegistry`（仅共享 owner），并通过 `wrapped_tool_name` 生成 `mcp_<server>_<tool>` 命名空间避免租户间碰撞。
- 安全层：`network.py` 实现 SSRF 防护，区分管理员宽松策略与 self-service strict 策略（额外阻断 loopback/RFC1918），并在每次请求时重校验；`secrets.py` 用 `${secret:<server>/<field>}` 引用代替明文，值存于 owner 专属的 `private/mcp/*.json`；`oauth.py` 基于 MCP SDK 的 `OAuthClientProvider`，将 token/client 注册存于 `private/mcp-oauth/<server>.json`，非交互路径抛出 `AuthorizationRequired` 而非阻塞 consent 屏幕。
- 目录层：`catalog/loader.py` 从包内 `vendor/curated.json` 缓存解析后的条目，提供搜索/分页 API，不触网。
- 会话层：`session_state.py` 把已加载 deferred tool 的 schema 持久化到 session workspace 的 `loaded_tools.json`。

依赖方向单向：manager → (config, user_config, network, secrets, oauth)；catalog 独立只读；所有对 `mcp` SDK 的 import 都延迟到函数体内以避免可选依赖导致启动失败。
