模块按职责拆分为四个子文件，依赖方向单向向外：
- `llm.py`：定义 `LLMSelection`（仅含 ID 的安全引用）与 `VALID_REASONING_EFFORTS` 白名单，提供 `list_llm_options`（从 catalog 的 `services.llm.profiles` 枚举可用模型并标注 provider_label / context_window / reasoning_effort / supports_vision）和 `apply_llm_selection_to_catalog`（复制 catalog 并改写 active_profile_id/active_model_id）。
- `runtime.py`：通过 `contextvars` 在异步上下文内安装/重置 scoped `LLMConfig`，对外暴露 `activate_llm_selection` / `reset_llm_selection`，内部把 `ResolvedLLMConfig` 适配为 `LLMConfig`。
- `tasks.py`：独立于 chat 服务维护 `services.task`，用 `TaskKind` StrEnum 标记每个后台调用（SESSION_TITLE / CHAT_STARTERS / READING_* 等），支持 inherit / reference / profiles 三种 mode；`task_llm_scope` 作为 contextmanager 在块内注入 task 模型，失败时静默回退到继承模式。
- `reasoning.py`：根据 binding + model + catalog metadata 推导各后端支持的 reasoning effort 列表，优先走 `codex_supported_reasoning_levels`，否则按 provider/family 硬编码映射。
- `task_agent.py`：基于 tasks 配置构造绑定到 task 模型的轻量 agent，供 subagent 使用。

入口由 `__init__.py` 只导出 LLM 侧 API；catalog 结构被当作不可变数据读取并通过 `deepcopy` 派生视图，避免污染全局设置。
