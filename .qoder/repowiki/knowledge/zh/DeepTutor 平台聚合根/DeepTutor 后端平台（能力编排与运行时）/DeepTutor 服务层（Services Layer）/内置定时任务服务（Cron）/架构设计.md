模块按职责拆分为四个文件：
- `service.py` 暴露核心数据模型（`CronSchedule`/`CronOwner`/`CronJob`/`CronRunRecord`/`CronJobState`）、调度算法（`compute_next_run`、`validate_schedule`）和 `CronService`——后者维护内存快照 `_jobs`、通过 `asyncio.Event` 唤醒的 `_loop` 轮询 due 任务，并调用注入的 `on_job` 回调。
- `repository.py` 定义 `CronRepository` Protocol 接口与 `SQLiteCronRepository` 实现，使用 WAL + busy_timeout=30s 的 SQLite 表 `cron_jobs`（payload 以 JSON 文本存储）+ `cron_meta`（singleton revision），并通过文件级互斥锁（`fcntl`/`msvcrt`）在首次打开时把旧 `jobs.json` 迁移进数据库。
- `executor.py` 是 `on_job` 的具体实现，根据 `owner.kind` 分派到 `_execute_chat_job`（通过 `turn_engine` 执行一轮 chat 并把用户/助手消息写回 session store）或 `_execute_partner_job`（向 partner runner 投递 `InboundMessage` 再经 bus 发布 `OutboundMessage`），并在 macOS 上尝试 `osascript` 桌面通知。
- `module_service.py` 暴露 `start_cron`/`stop_cron` 作为安装模块的后台服务钩子；`__init__.py` 统一导出公共 API，`get_cron_service()` 懒加载单例，路径锚定在 admin workspace 下的 `cron/jobs.sqlite3`。
依赖方向单向：`module_service → service → executor`，`service` 仅依赖 `repository.Protocol`，不感知具体存储实现。
