- 所有持久化后端都通过实现 `protocol.py` 中的 `SessionStoreProtocol` / `SessionRepository` / `TurnRepository` / `MessageRepository` 协议来接入，上层代码只依赖这些 Protocol 而非具体类。
- 对请求参数进行类型与范围校验时统一使用模块内 `_xxx(value, default)` 归一化工具函数（如 `_coerce_bool`、`_reading_material_id`、`_workspace_mode`），失败时返回默认值而非抛错。
- 需要跨进程或跨 worker 的状态变更一律通过 `transition_turn(..., fencing_token=...)` 带 fence 的乐观更新完成，而不是直接写 status。
- 长耗时或可能阻塞 I/O 的依赖（如 `learning.storage.LearningStore`、`ReadingStore`、`pocketbase_client.get_pb_client`）采用方法体内局部 import，避免启动期循环导入与冷启动开销。
- 会话/工作区作用域通过 `store_scope(store).cache_key` 计算标识，并在 `get_session_store` 与 `get_turn_runtime_manager` 中以该 key 做进程内单例缓存。
- 对 LLM 生成的自由文本（标题、答案片段）在进入持久化前会经过清洗管线（`clean_thinking_tags`、截断、CJK 强调修复、错误前缀检测）。
