模块按职责分层：
- `base.py` 定义 `BaseTTSAdapter` / `BaseSTTAdapter` 抽象基类、`VoiceProviderError` 异常族、`TranscriptCue` 数据结构，以及 `synthesize_with_timeout`、`build_auth_headers`、`join_audio_path`、`strip_markdown_for_speech` 等跨适配器的共享工具。
- `config.py` 通过 `TTSConfig` / `STTConfig` dataclass(slots=True) 暴露运行时配置，并声明认证头风格常量（bearer / api_key_header / token）与 STT 请求编码（multipart / base64_json），作为模型目录到 HTTP 适配器的只读桥接层。
- `adapters/__init__.py` 维护 `TTS_ADAPTERS` / `STT_ADAPTERS` 两个全局单例字典，由 `get_tts_adapter` / `get_stt_adapter` 按 `adapter` 字段分发；每个具体供应商实现一个文件（dashscope、edge、gemini、mimo、minimax、mistral、openai_compat、volcengine、xai），统一继承 `Base*Adapter`。
- `__init__.py` 是对外门面，暴露 `synthesize_speech` / `transcribe_audio` / `transcribe_audio_cues`，内部通过 `provider_runtime.resolve_*_runtime_config` 解析 catalog 选择后委托给对应适配器。
- `discovery.py` 负责在运行时向 MiniMax/DashScope 控制面拉取可用 voice 列表，不绑定任何静态 voice ID。
- `options.py` 提供 UI 用的模型/语言/格式预设，与 discovery 分离——voice ID 永远动态发现。
- `audio.py` 提供 PCM↔WAV 转换与 ffmpeg 规范化，供原生 STT 适配器复用。
依赖方向单向：门面 → 适配器注册表 → 具体适配器 → base/config/audio；适配器之间互不引用。
