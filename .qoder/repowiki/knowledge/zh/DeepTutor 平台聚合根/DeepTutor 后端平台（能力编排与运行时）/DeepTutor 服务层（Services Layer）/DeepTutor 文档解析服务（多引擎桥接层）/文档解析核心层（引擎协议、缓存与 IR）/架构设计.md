模块按职责分为五个内聚子单元，依赖方向单向：
- `base.py` 通过 `@runtime_checkable` Protocol 定义 `Parser` 契约（`resolve_config` / `supported_formats` / `signature` / `is_ready` / `parse`），并声明 `ReadinessReport` 作为就绪性报告；这是本模块对外的唯一抽象边界。
- `types.py` 定义桥接 IR `ParsedDocument`（markdown + blocks + asset_dir + engine/metadata）以及统一的 `ParserError` 异常基类，供所有引擎和消费者共享。
- `service.py` 中的 `ParseService` 是公共入口：读取运行时配置选择默认引擎，调用 `engines.factory.get_parser` 获取具体实现，先做格式匹配与 `_FALLBACK_ENGINE_PREFERENCE`（text_only → markitdown → tika）回退，再计算 `(source_hash, parser_signature)` 查缓存，未命中则执行 `is_ready` 门控后调用引擎 `parse`，最后写 manifest 并返回 `ParsedDocument`。
- `cache.py` 实现内容寻址文件系统缓存，目录布局为 `parse_cache/<hash[:2]>/<source_hash>/<signature>/manifest.json`，通过 `atomic_write_json` 原子写入 manifest 作为完成标记，并提供 `load_ir` 将磁盘产物还原为 `(markdown, blocks, asset_dir)`，同时修正 MinerU 相对 `img_path`。
- `signature.py` 的 `ParserSignature` 仅对影响产出的配置参数做稳定哈希，与 RAG 的 `EmbeddingSignature` 对齐，确保同一份字节 + 同一份输出相关配置可命中缓存。
- `progress.py` 基于 `ContextVar` 暴露可选的 `ParseProgress` 上下文，在 `ParseService.parse` 中注入阶段与文档状态，并通过 `_redact` 脱敏错误信息、`failure_code` 归类失败原因。

依赖方向：`service` → (`cache`, `signature`, `types`) + `engines.factory`；`base` 仅依赖 `signature`；`progress` 无内部依赖。引擎实现位于同包下的 `engines/` 子包，本模块不直接 import 任何具体引擎。
