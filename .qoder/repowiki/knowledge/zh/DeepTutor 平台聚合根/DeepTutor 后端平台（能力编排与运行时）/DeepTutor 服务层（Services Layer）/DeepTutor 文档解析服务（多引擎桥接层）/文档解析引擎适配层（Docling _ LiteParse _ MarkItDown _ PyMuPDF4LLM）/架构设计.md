每个子目录对应一个第三方解析器（docling、liteparse、markitdown、pymupdf4llm），采用一致的三文件结构：
- `engine.py`：实现上层 `Parser` 协议（`is_available` / `resolve_config` / `supported_formats` / `signature` / `is_ready` / `verify` / `parse`），通过 `importlib.util.find_spec` 惰性检测依赖是否安装。
- `config.py`：定义 frozen dataclass 配置并暴露 `resolve_<engine>_config()`，从 `runtime_settings.load_document_parsing_settings()` 读取切片。
- `formats.py`：维护最小兼容版本常量与扩展名 frozenset，并提供 `installed_*_version` / `*_version_is_current` 比较函数；为避免导入重型 ML 运行时（如 Docling 的 Transformers/PyTorch），格式表是静态快照而非动态查询。

Docling 额外拆出 `local_worker.py`（本地进程内转换）和 `remote.py`（HTTP Serve 调用），由 `engine.parse` 根据 `config.is_remote` 分派；同时通过 `DOCLING_CACHE_DIR` / `HF_HOME` 探测模型缓存目录以完成 `is_ready` 中的 `models_missing` 分支。其余三个引擎均为纯本地模式。

所有引擎统一将输出写入 `<workdir>/<stem>.md`，并在支持图片时按 MinerU/Docling 约定写入 `<workdir>/images/<name>` 并将 Markdown 中的链接重写为相对 `images/<name>` 形式，从而被上游缓存加载器消费。
