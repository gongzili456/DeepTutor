模块以 `engine.py` 中的 `MinerUParser` 作为对外入口，实现上层 `Parser` 协议；内部按职责分层：
- 配置层 `config.py`：通过 `resolve_mineru_config()` 从 `document_parsing.json` 适配出不可变的 `MinerUConfig` dataclass，集中处理 mode/local/cloud、模型下载源、语言、公式/表格开关、PDF 分片上限等。
- 分发层 `backend.py`：提供 `parse_document_to_workdir` / `parse_pdf_to_workdir`，依据 `cfg.is_cloud` 在 `local.py` 与 `cloud.py` 之间路由，并封装 CLI 探测 (`local_cli_probe`, `local_cli_version`) 与失败消息映射 `_LOCAL_FAILURE_MESSAGES`。
- 本地后端 `local.py`：通过 `_process.py` 启动外部 `mineru`/`magic-pdf` 子进程，使用临时 attempt 目录 + `atomic_write_json` 状态文件实现可中断、可重试的幂等解析，返回带 `LocalParseReason` 的 `LocalParseResult`。
- 云端后端 `cloud.py`：基于 httpx 调用 `/api/v4/file-urls/batch` → PUT signed URL → 轮询 `extract-results/batch/{batch_id}` → 下载 zip 解压，内置 KeyPool 多 token 轮换、429 自动退避、PDF 自动切片（`_split_pdf` + `_merge_part_artifacts`）与 `checkpoints.SliceCheckpoint` 断点续传。
- 辅助层：`formats.py` 维护支持格式白名单；`models.py` 提供 HuggingFace 镜像环境变量注入；`normalization.py` 提供云端的 `working_copy` 预处理；`readiness.py` 实现“禁止静默下载”的前置检查门控；`_process.py` 封装子进程生命周期。
依赖方向单向：engine → backend → {local|cloud}，所有异常统一收敛为 `MinerUError(ParserError)`，使上层批处理能隔离单文档失败。
