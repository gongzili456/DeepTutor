模块以 `service.py` 的 `SandboxService` 作为唯一对外门面，通过 `config.build_backend` 按部署形态选择后端：优先 `RunnerSidecarBackend`（HTTP 调用独立 runner 容器）、其次 Linux 上的 `BwrapBackend`（bubblewrap mount namespace）、最后退化为 `RestrictedSubprocessBackend`（仅 PATH/ENV 清理，需显式开启）。`backends.py` 定义抽象基类 `SandboxBackend` 及三个实现，统一暴露 `level: IsolationLevel`（SYSTEM / APPLICATION / OFF）供上层策略门控；`spec.py` 提供与后端无关的 frozen dataclass 契约（`ExecRequest`、`ExecResult`、`Mount`、`ResourceLimits`），被 skill/exec 层与后端双向引用。`quota.py` 用 asyncio.Semaphore + deque 实现 per-user 并发与滑动窗口速率限制，在 `run()` 中通过 `_Lease` 上下文管理器保证释放。`artifacts.py` 扫描工作区可见文件生成 `SandboxArtifact` 列表，区分 workspace binding 与公共输出路径两种暴露模式。`runner/server.py` 是独立的零第三方依赖 HTTP 服务器（`http.server`），运行在专用 sandbox-runner 容器中，通过 `/health` 与 `/exec` 协议与主进程通信，并使用 `resource.setrlimit` 施加内存/CPU/文件描述符上限。健康探测带异步缓存与锁，并在 bwrap 失败时自动回退到 subprocess 后端。
