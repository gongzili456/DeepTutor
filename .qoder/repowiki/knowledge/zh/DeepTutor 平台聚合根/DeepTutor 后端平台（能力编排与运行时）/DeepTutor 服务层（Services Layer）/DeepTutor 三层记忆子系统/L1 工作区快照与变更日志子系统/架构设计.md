模块按职责拆分为四个文件，依赖方向单向：`entity.py` → `diff.py` ← `adapters.py` / `store.py` → `__init__.py`（对外门面）。
- `entity.py`：纯 dataclass 类型定义（`Entity` / `EntityStamp` / `ChangeEntry`）与 `Stamped` Protocol，不含任何 I/O，作为整个子系统的契约层。
- `adapters.py`：每个 surface（notebook/cowriter/book/partner/kb/chat/quiz）一个 `read_*_entities()` 函数，从磁盘或 SQLite 读取原始数据并构造 `list[Entity]`；通过 `_READERS` 字典按 surface 名分派。对 chat 额外提供 `probe_chat_entities()` 走轻量 SQL 路径返回 `EntityStamp`，由 `_PROBES` 表驱动，`read_stamps()` 在 probe 失败时回退到 full read 投影。
- `diff.py`：纯函数 `diff_snapshots(prev_fp, curr_fp, label_map, prev_label_map)`，仅比较 `{id: fingerprint}` 映射，产出 `added/modified/removed` 三类 `ChangeEntry`。
- `store.py`：以 `<memory_root>/snapshot/<surface>/` 为根目录，`state.json` 用 temp-file + `os.replace` 原子写入，`changes.jsonl` 追加行式 JSON（每行一个 `ChangeEntry`），读写均容忍损坏文件并记录 warning。
- `__init__.py`：对外暴露 `read_snapshot` / `read_stamps` / `pending_changes` / `refresh_snapshot` / `read_changes` / `current_state` / `clear_changes`，将 adapters 的读、diff 的计算、store 的写组合成无副作用的编排函数；`refresh_snapshot` 仅在 stamps 上运行以避免加载消息体内容。
