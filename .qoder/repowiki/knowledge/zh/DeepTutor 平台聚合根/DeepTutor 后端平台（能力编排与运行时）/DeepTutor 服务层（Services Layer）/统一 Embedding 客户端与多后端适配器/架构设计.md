模块以 `client.py` 中的 `EmbeddingClient` 作为唯一对外入口，按 `services.config.provider_runtime.EMBEDDING_PROVIDERS` 映射表把用户配置的 `binding`（如 openai、cohere、jina 等）解析到 `adapters/__init__.py` 中注册的 `ADAPTER_BACKENDS` 实现类。

- 分层：`config.py` 从 model catalog 解析出 `EmbeddingConfig`（含 binding/model/api_key/dim/batch_size/batch_delay 等），并通过 `ContextVar` 提供 `embedding_config_scope` 让一次任务及其 worker 线程共享同一配置；`validation.py` 对 provider 返回的向量做类型/维度/有限性校验；`request_options.py` 集中处理 `dimensions` 请求参数的三态策略（显式 True/False 或按模型族自动推断）。
- 适配器层：`adapters/base.py` 定义抽象基类 `BaseEmbeddingAdapter` 及 `EmbeddingRequest` / `EmbeddingResponse` / `EmbeddingProviderError` 数据结构，每个 provider 一个文件（openai_sdk、openai_compatible、cohere、jina、ollama、dashscope_native、gemini、nvidia_nim），由 `adapters/__init__.py` 统一注册到 `ADAPTER_BACKENDS`。
- 依赖方向：client → adapters.base + config + validation；adapter 仅依赖 base 和 `deeptutor.services.keypool.KeyPool` 做 API Key 轮转；顶层 `__init__.py` 使用 `__getattr__` 延迟导入 client/adapters 子模块，避免在仅读取模型元数据时初始化所有 SDK。
- 并发与节流：`EmbeddingClient` 用进程级 `threading.Lock` + `asyncio.sleep` 轮询实现跨 event loop 的请求间隔（`batch_delay`），并限制每批大小不超过 provider 的 `max_batch_items`。
