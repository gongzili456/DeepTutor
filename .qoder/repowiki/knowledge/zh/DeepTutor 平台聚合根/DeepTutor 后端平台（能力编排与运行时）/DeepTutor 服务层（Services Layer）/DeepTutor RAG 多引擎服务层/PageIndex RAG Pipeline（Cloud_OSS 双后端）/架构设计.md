模块按职责拆分为六个文件，形成清晰的内部分层：
- `pipeline.py` 暴露 `PageIndexPipeline`，实现上层 `RAGPipeline` 契约（`initialize`/`add_documents`/`delete`/`remove_document`/`document_map`），但 `search()` 故意返回“需通过 Agent 工具读取”的错误，强制走 reasoning 路径。
- `client.py` 提供 `PageIndexClient` 异步门面，封装同步的 `pageindex.PageIndexCloudClient` / `PageIndexLocalClient`，并通过 `asyncio.to_thread` 把 SDK 调用转到线程；Cloud 端用 `lru_cache` 复用 MCP 会话，OSS 端从 LLM 配置解析出 `index_model`/`backend` 传给 Local Client。
- `storage.py` 维护 KB 本地 manifest（`pageindex_docs.json` + `meta.json`），仅记录 `doc_id` 映射，无向量嵌入；借助 `deeptutor.services.rag.index_versioning` 的 version-N 目录结构让 UI 识别就绪状态。
- `tools.py` 将 SDK 暴露的 OpenAI tool schema 包装为 `BaseTool`（`PageIndexSDKTool`），按 provider 加前缀（`pageindex_cloud_` / `pageindex_oss_`），并通过 `ScopedToolRegistry` 注入到工作流上下文。
- `reasoning.py` 定义 `_ReadingHost` 与 `read_pageindex_with_agent`，基于 `run_agentic_loop` 运行 THINK/TOOL/FINISH 协议，驱动带工具的推理式检索。
- `config.py` 集中加载运行时设置中的 `api_key`，对外暴露 `PageIndexConfig`。
依赖方向单向：`reasoning` → `tools` → `pipeline` → (`client`, `storage`, `config`)，不反向依赖。
