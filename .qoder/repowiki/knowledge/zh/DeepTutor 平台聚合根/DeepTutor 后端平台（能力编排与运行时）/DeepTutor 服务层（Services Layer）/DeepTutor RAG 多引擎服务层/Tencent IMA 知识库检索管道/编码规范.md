- 对外 API 错误被统一转换为带 `error_type` 字段的字典结果（如 `authentication_error`、`rate_limited`、`timeout`、`network_error`、`content_unavailable`），由 `ImaPipeline._error_result` 集中映射。
- HTTP 请求通过 `ImaTransport.post` / `post_sync` 以方法名字符串（如 `"search_knowledge"`）路由，避免硬编码 URL，签名与超时集中在 transport 层。
- 外部响应一律经 `models.py` 中的 `parse_*` 函数转为 Pydantic 模型后再向上返回，禁止直接透传原始 dict。
- 分页与批量参数通过 `page_limit` 等工具函数钳制到 IMA 文档规定的范围（`MAX_PAGE_LIMIT=50`、`MAX_DETAIL_IDS=20`、`MAX_IMPORT_URLS=10`、`_MAX_SEARCH_PAGES=3`）。
- 配置采用双层合并：KB 级 `kb_config.json` 字段优先，缺失时回退到账户级 `settings/ima.json`，最终由 `resolve_kb_config` 产出不可变的 `ImaConfig` dataclass。
- 对 IMA 的写操作（上传、删除）不在本模块内实现：`initialize`/`add_documents` 抛出明确异常，`delete` 作为 no-op 仅移除 DeepTutor 指针，避免触碰用户库。
