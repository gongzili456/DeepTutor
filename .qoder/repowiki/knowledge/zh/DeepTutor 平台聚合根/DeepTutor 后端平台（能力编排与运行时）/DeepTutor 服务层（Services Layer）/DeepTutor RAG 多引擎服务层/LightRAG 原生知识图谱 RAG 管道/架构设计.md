模块以 `pipeline.LightRagPipeline` 为对外入口，实现上层 `RAGPipeline` 契约（initialize/add_documents/search/delete），内部按职责拆分为若干子模块：
- `engine.py`：精确锁定 `lightrag-hku==1.5.7`，动态继承 LightRAG 类并注入 DeepTutor 自定义 parser（`deeptutor` 引擎），负责构建 rag 实例、enqueue/reconcile/finalize 生命周期以及查询结果到统一 source 结构的转换。
- `config.py`：可选依赖隔离层，通过 `importlib.util.find_spec` 探测 LightRAG 是否安装；将 DeepTutor 的 LLM/vision/embedding 客户端包装成 LightRAG 所需的 `llm_model_func`/`vision_model_func`/`EmbeddingFunc`，并提供带重试的 `_run_adapter_with_retry`。
- `storage.py`：定义 `<kb_dir>/version-N/` 扁平布局与 `meta.json` 元数据（provider/signature/workspace/parser_inputs/indexing_policy/embedding_signature），提供 published 判定、embedding 兼容性校验与失败摘要。
- `ingress.py` + `parser.py` + `block_policy.py`：文档入站、MinerU block 分类与审计账本写入。
- `indexing_policy.py` + `roles.py` + `cache_reuse.py`：角色快照（EXTRACT/KEYWORD/QUERY/VLM）、推理能力、缓存复用策略。
- `worker.py` + `write_lock.py` + `sidecar.py`：跨线程事件循环桥接、KB 级写锁与 sidecar 进程协调。
依赖方向单向向外：pipeline → engine/config/storage/ingress/policy/roles → worker/write_lock/sidecar；LightRAG SDK 仅在 `engine` 和 `config` 中按需 import，保证其他 RAG provider 可无额外依赖导入本包。
