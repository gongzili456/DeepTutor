每个子目录对应一个外部后端，结构高度一致：
- `pipeline.py` 暴露 `XxxPipeline` 类，实现统一的 `search`/`initialize`/`add_documents`/`delete` 异步契约；`search` 通过 `load_kb_config_entry` 读取 `kb_config.json` 中的 KB 绑定，再调用本地 `client.py` 发起 HTTP 请求。
- `client.py` 封装各后端的 HTTP 调用（如 Kiwix 的 ZIM 搜索、LightRAG 的 `/query`、WeKnora 的 `/documents/search`）。
- `config.py`（LightRAG Server 与 WeKnora 有，Kiwix 无）定义 frozen dataclass 配置对象和 `config_from_entry` 解析函数，并抛出专用的 `*NotConfiguredError`。
- `probe.py`（LightRAG Server 与 WeKnora 有）提供连接前探测能力，返回带 `ok`/`reachable`/`error` 等字段的 dataclass，供 UI 在创建 KB 时校验远端可达性与凭据。
依赖方向单向向外：pipeline → client/config/probe → 外部 HTTP 服务；模块内部不持有全局状态，所有可注入点（`client_factory`、`kb_base_dir`）均通过构造参数传入以支持测试替换。
