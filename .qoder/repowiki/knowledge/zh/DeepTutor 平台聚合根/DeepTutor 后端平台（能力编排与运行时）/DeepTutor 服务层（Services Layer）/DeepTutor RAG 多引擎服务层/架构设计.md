本模块采用「工厂 + 管道 + 共享基础设施」三层结构：
- 顶层 `factory.py` 维护 `KNOWN_PROVIDERS` 常量与 `_PIPELINE_CACHE`，按 `(kb_base_dir, provider)` 键缓存实例；`get_pipeline()` 通过延迟 import 按需加载具体 pipeline 类，未知 provider 回退到默认 `llamaindex`。
- `pipelines/<provider>/pipeline.py` 每个子目录实现一个 `RAGPipeline` 子类（继承自 `pipelines/base.py`），封装各自的文档解析、索引、检索与存储细节；外部后端（IMA/WeKnora/Kiwix/LightRAG Server）走 HTTP/OpenAPI 而不本地建索引。
- 共享基础设施集中在本目录顶层：`index_probe.py`/`index_versioning.py` 提供跨 provider 的版本就绪探测与签名匹配；`preflight.py` 做启动前依赖检查；`linked_kb.py`/`kb_paths.py` 管理知识库路径；`embedding_binding.py`/`embedding_signature.py`/`provider_binding.py` 将 embedding 模型与 provider 绑定；`smart_retriever.py`/`query_rewrite.py`/`source_pages.py`/`source_visuals.py`/`visual_assets.py`/`visual_coverage.py` 在检索后对结果进行重排、溯源与可视化覆盖统计。
- `eval/` 是独立于运行时的离线评估子系统，复用同一套 pipeline 契约对 Recall@k、nDCG@k、MRR 等指标打分并生成 diff 报告。
- 所有 provider 的 readiness 信息通过 `list_pipelines()` 聚合返回给 UI 选择器，各 provider 的 `config.is_*_available()` 被 try/except 包裹以避免缺失可选依赖导致启动失败。
