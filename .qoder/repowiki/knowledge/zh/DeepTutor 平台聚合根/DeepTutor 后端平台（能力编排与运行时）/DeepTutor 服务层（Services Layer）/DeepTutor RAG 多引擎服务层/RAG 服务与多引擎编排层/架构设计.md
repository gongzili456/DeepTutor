模块以 `service.RAGService` 为对外统一入口，通过 `factory.get_pipeline` 按 provider 名称（llamaindex/pageindex/graphrag/lightrag/lightrag-server/ima/weknora/kiwix）动态加载对应 `pipelines/<engine>/pipeline.py` 中的 Pipeline 实现；provider 选择优先使用构造时传入的 override，否则走 `provider_binding.resolve_bound_provider` 读取 KB 配置。

内部分层：
- 顶层门面：`service.py`（`RAGService`，封装初始化/增量索引/搜索/删除/智能检索）、`factory.py`（provider 常量 + `_PIPELINE_CACHE` + `_build_pipeline` 分派）、`__init__.py` 暴露公共 API。
- Provider 绑定与版本：`provider_binding.py`、`embedding_binding.py`、`embedding_signature.py`、`index_versioning.py`、`index_probe.py`、`kb_paths.py` 负责 KB 目录解析、嵌入签名、版本就绪检查与失败摘要。
- 横切能力：`query_rewrite.py`（查询改写 fail-open 层）、`smart_retriever.py`（多查询扩展）、`file_routing.py`（文档类型路由）、`source_pages.py` / `source_visuals.py` / `visual_assets.py` / `visual_coverage.py`（来源页与视觉资源处理）。
- `pipelines/` 子包：每个引擎一个子目录，统一遵循 `base.RAGPipeline` Protocol（`initialize`/`add_documents`/`search`/`delete`），但允许通过 `hasattr` 探测可选方法（如 `delete`）保持向后兼容。
- `eval/` 独立子包：评估数据集、匹配、指标、报告与 Runner，不依赖 pipelines 实现。

依赖方向单向：service → factory → pipelines；versioning/probe/path 等工具被 service 和 pipeline 共享；外部引擎（graphrag、lightrag、pageindex SDK、ima/weknora REST）仅在需要时 import，避免启动期强依赖。
