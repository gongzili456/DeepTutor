模块以 `pipeline.py` 中的 `GraphRagPipeline` 为对外入口，实现与 `LlamaIndexPipeline` 一致的 `initialize/add_documents/search/delete` 异步契约；内部按职责拆分为：
- `config.py`：把 DeepTutor 的 LLM + embedding 运行时配置生成 GraphRAG 的 `settings.yaml`（仅填充 completion/embedding model、input/output/storage/cache/vector_store），是 GraphRAG schema 变更的唯一适配点。
- `provider.py`：在 LiteLLM 边界映射 DeepTutor provider → graphrag_llm 支持的 transport（anthropic/azure/deepseek/openai），拒绝 OAuth-only 与不支持的后端。
- `engine.py`：唯一直接 import `graphrag` 的模块，封装 `build_index`、`global/local/drift/basic_search`、结构化输出 probe、embedding probe；通过 `_run_isolated` 在独立 asyncio 事件循环中运行以绕过 uvloop/nest_asyncio2 冲突。
- `ingestion.py`：DeepTutor 文档 → `.txt` 输入文件（GraphRAG 不自行解析）。
- `storage.py`：定义 KB 版本目录布局 `<kb_dir>/version-N/{settings.yaml,input,output,cache,logs,meta.json}`，用 parquet 表存在性判定索引就绪。
- `completion_adapter.py` / `pandas_compat.py` / `errors.py`：LiteLLM 完成适配器注册、Arrow 扩展预加载、分类错误类型。
依赖方向单向：pipeline → {config, ingestion, storage, engine}，engine → {config, provider, errors, pandas_compat}，provider/errors 无内环依赖。GraphRAG 通过 `is_graphrag_available()` + 方法级延迟 import 保持为可选依赖。
