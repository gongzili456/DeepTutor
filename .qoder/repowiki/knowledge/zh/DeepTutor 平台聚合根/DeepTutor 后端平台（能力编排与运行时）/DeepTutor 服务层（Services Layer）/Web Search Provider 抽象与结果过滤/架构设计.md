模块以 `base.py` 中的 `BaseSearchProvider` ABC 作为统一接口：每个 provider 实现 `search(query, **kwargs) -> WebSearchResponse`，并通过 `providers/__init__.py` 的 `@register_provider` 装饰器注册到内部 `_PROVIDERS` 字典，由 `get_provider` / `get_default_provider` 按 Settings > Search 配置解析并实例化。

- `types.py` 定义跨 provider 共享的数据契约：`Citation`、`SearchResult`、`WebSearchResponse`（含 `to_dict` 向后兼容）。
- `consolidation.py` 的 `AnswerConsolidator` 在 raw SERP 结果上通过 Jinja2 模板（`serper`/`jina`/`serper_scholar` 三套内置模板 + 通用回退）或可选 LLM 合成生成最终 `answer`；依赖 `deeptutor.services.llm.get_llm_client`。
- `source_filter.py` 提供 `filter_web_search_response`，对 `citations` 与 `search_results` 执行四级过滤链：URL 合法性/端口/IP/域名白黑名单 → 标题+snippet 正则内容启发式 → 可选 OpenAI Moderation 批量审核 → 可选 Google Web Risk Lookup（带线程池并发、900s TTL 缓存、去重），失败均 fail-open 不阻断搜索。
- `providers/` 下每个文件是一个第三方后端的具体实现（Serper、Jina、Perplexity、Tavily、DuckDuckGo、SearXNG、Google Browser Scraper、Firecrawl、You.com、阿里 IQS、博查、豆包、千帆、智谱等），全部继承 `BaseSearchProvider`，凭据从 `deeptutor.services.config.search_provider_credentials` 读取，而非环境变量。

依赖方向：providers → base/types → consolidation/source_filter → 外部服务（OpenAI Moderation、Google Web Risk、LLM client），模块自身不直接暴露 HTTP 调用给上层。
