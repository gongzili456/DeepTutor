模块以 `base.SubagentBackend` 抽象类为核心契约，每个外部 agent 实现一个后端类（`claude_code.py`、`codex.py`、`grok.py`、`antigravity.py`、`kimi.py`、`hermes.py`、`openclaw.py`、`deepseek_harness.py`、`opencode_family.py`），由 `registry._BACKENDS` 集中注册并通过 `get_backend()` / `detect_all()` 暴露；`partner.py` 和 `hermes_remote.py` 是两种非本地进程变体——Partner 通过 partner manager 的 web turn 协议复用用户侧对话，HermesRemote 通过 `hermes_remote_client.HermesRemoteClient` 走 httpx + SSE 连接远端 Hermes Gateway。

内部分层清晰：
- 契约与值类型层：`base.py`（`SubagentBackend` 抽象 + `OnEvent` 回调）、`types.py`（`SubagentEvent`/`ConsultResult`/`DetectResult` 及 `EVENT_*` 常量）作为跨边界稳定 API。
- 共享基础设施层：`process.py` 提供 `stream_process_lines`（按行流式读取子进程 stdout/stderr 并保证退出后清理）、`probe_version`、`resolve_cli_command`（PATH/PATHEXT 兼容 Windows npm shim）；`config.py` 管理 `subagent.json` 中的 `consult_budget` 与每后端 `permission_mode`/`sandbox`/`approval` 等无头运行参数。
- 传输适配层：`hermes_remote_client.py` 封装 httpx + SSE 协议；`opencode_server.py` 管理 opencode 家族的后端进程；`hermes_remote_events.py` 解析 Hermes 事件。
- 配置与发现层：`registry.py` 是唯一知道所有后端的入口，`local_cli=True` 或 `detectable=True` 的后端参与自动探测。

依赖方向单向向内：具体后端 → base/types/config/process → 上层 consult tool / API / UI 仅看到 `__init__.py` 导出的稳定集合，不感知任何 CLI 协议细节。
