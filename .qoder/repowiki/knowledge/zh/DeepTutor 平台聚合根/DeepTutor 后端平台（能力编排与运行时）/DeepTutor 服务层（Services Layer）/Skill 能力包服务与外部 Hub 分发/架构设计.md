模块按职责拆分为五个文件：
- `service.py` 是核心层，定义 `SkillService`（CRUD + 清单渲染 + 运行时 eager/inject）、`SkillInfo/Detail/SummaryEntry/InstallResult` dataclass 及一整套异常类型；通过 `BUILTIN_SKILLS_ROOT` 与用户根目录构成「builtin 只读 + user 可写」双层模型，user 层 shadow builtin。
- `hub.py` 提供外部注册表抽象 `SkillHubProvider` Protocol，内置 `ClawHubProvider`（直接 HTTP 调用 `/api/v1`）和 `CommandProvider`（包装任意 fetch 命令），由 `get_hub_provider` 从 `settings/skill_hubs.json` 解析并合并 `_BUILTIN_HUBS`；`install_from_hub` 编排 verify→fetch→install 流水线，并把结果交给 `SkillService.install_tree` 做导入策略校验。
- `runtime.py` 在请求上下文中组装多来源 SkillService（workspace → account → admin granted → builtin），暴露 `skill_manifest()` / `resolve_runtime_skill()` 供上层 prompt 构建使用。
- `credentials.py` 单独维护 `skill_hub_auth.json`（0600 权限）中的 hub bearer token，与可共享的 `skill_hubs.json` 分离。
- `taxonomy.py` 是 EduHub 分类体系的 Python 单点真相（track/language/stage/form/audience/domains），与前端 `eduhub-web` 值对齐，供 publish/update 交互流程复用。
依赖方向单向：`runtime` → `service`；`hub` → `service`；`credentials` 独立；`taxonomy` 被 `hub` 用于发布表单。所有外部 I/O（sandbox、path_service、httpx、yaml）均通过 late import 或显式参数注入以保持可测试性。
