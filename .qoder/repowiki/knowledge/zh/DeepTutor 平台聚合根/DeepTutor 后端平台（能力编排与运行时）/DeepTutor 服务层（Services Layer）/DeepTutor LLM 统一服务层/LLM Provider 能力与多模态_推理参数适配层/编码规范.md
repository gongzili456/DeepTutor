- 能力值通过 `get_capability(binding, capability, model)` 统一解析，依次查找 catalog 用户覆盖 → MODEL_OVERRIDES（按最长前缀匹配）→ PROVIDER_CAPABILITIES → DEFAULT_CAPABILITIES → 显式 default。
- 对每个 provider 在 `PROVIDER_CAPABILITIES` 中声明一组布尔型 capability 键（如 `supports_response_format`、`supports_streaming`、`supports_vision`、`system_in_messages`、`has_thinking_tags`、`vision_url_supported`、`requires_api_version`），模型级差异通过 `MODEL_OVERRIDES` 前缀覆盖。
- 运行时发现的 API 不兼容（如 response_format 被拒、forced tool_choice 被拒）通过 `disable_*_at_runtime` 写入模块级 set 缓存，并由对应的 `is_*_disabled_at_runtime` 在后续查询中优先返回 False。
- 多模态层采用两阶段策略：Stage-1 乐观注入所有图片（不查 supports_vision），Stage-2 在请求失败后通过 `should_degrade_to_text` 决定是否 strip 图片重试，避免已知 vision 模型因偶发错误被误降级。
- 推理参数通过 provider/model 匹配表（`_PROVIDER_THINKING_STYLES`、`_PROVIDER_REASONING_PATTERNS`、`_CUSTOM_MODEL_THINKING_STYLES`）推断 thinking 风格，再由 `build_openai_compatible_reasoning_kwargs` 统一产出 kwargs，特殊 provider（minimax、openrouter）走分支处理。
