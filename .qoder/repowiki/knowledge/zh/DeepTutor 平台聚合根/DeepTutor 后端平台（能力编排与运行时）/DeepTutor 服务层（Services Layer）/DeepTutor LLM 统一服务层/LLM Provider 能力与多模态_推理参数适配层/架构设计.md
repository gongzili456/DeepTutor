本模块由三个职责互补的 leaf 文件组成：
- `capabilities.py` 是能力查询中心，通过 `PROVIDER_CAPABILITIES`（按 binding 声明）、`MODEL_OVERRIDES`（按 model 前缀覆盖）和运行时 `_CATALOG_OVERRIDES`（用户目录设置）三层叠加解析出 capability；对外暴露 `supports_response_format` / `supports_vision` / `has_thinking_tags` / `supports_tools` / `system_in_messages` / `requires_api_version` / `get_effective_temperature` 等便捷函数，并维护两个运行时缓存集合 `_RUNTIME_DISABLED_RESPONSE_FORMAT`、`_RUNTIME_DISABLED_FORCED_TOOL_CHOICE` 用于记录请求失败后动态关闭某项能力。
- `multimodal.py` 依赖 `capabilities.supports_vision_url` 决定是否需要 base64，把最后一条 user 消息的纯文本内容拆成 content-parts 数组并插入 OpenAI (`image_url`) 或 Anthropic (`image` source) 格式的图片块；提供 `prepare_multimodal_messages`（Stage-1 注入）、`strip_image_parts` / `strip_image_parts_inplace`（回退时替换为 `[image: ...]` 占位符）和 `should_degrade_to_text`（Stage-2 降级决策），并通过本地导入 `deeptutor.services.storage.get_attachment_store` 避免循环依赖。
- `reasoning_params.py` 独立于 capabilities，专注 OpenAI-compatible 的 thinking/reasoning 参数拼装：按 provider/model 匹配表选择 `thinking_type` / `enable_thinking` / `reasoning_split` 三种风格，处理 Gemini 默认开启 thinking 需显式关闭、OpenRouter 的 `reasoning.exclude`、MiniMax 的 `extra_body.thinking` 等厂商差异，并提供 `build_openai_compatible_reasoning_kwargs` 作为统一入口。
依赖方向：`multimodal.py` → `capabilities.py`；`reasoning_params.py` 不依赖同模块其他文件，三者均被上层 chat/agent 调用。
