本模块按职责分层组织：
- 顶层 `__init__.py` 通过 `factory.complete/stream/fetch_models` 暴露统一 API，并借助 `__getattr__` 惰性加载依赖重型 SDK 的 `cloud_provider`/`local_provider`，避免启动时导入。
- `orchestration`（client.py + factory.py）负责单例 LLMClient、重试/流式聚合、提供商路由；`provider_core` 定义 `LLMProvider` 抽象接口并提供各厂商适配；`capabilities` 集中声明 PROVIDER_CAPABILITIES/MODEL_OVERRIDES 能力矩阵；`transport` 封装 OpenAI/Anthropic HTTP 客户端与模型枚举。
- 跨子模块共享的契约集中在 `types.py`（Message/ToolChoice/StreamOutcome）、`exceptions.py`（LLMError 体系）、`reasoning_params.py`（thinking/reasoning 参数构造）以及 `usage_frame.py`/`usage_ledger.py`（用量统计），被 provider_core 与 orchestration 共同消费。
- 多模态路径由 `multimodal.py` 在消息进入 provider 前注入图片附件，`image_caption_*` 子模块负责本地 caption 缓存与回放，与 `capabilities.supports_vision` 联动。
