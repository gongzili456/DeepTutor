模块以 `capability.py` 中的 `DeepQuestionCapability` 作为 TurnCapability 入口，按 `mode` 路由到三条路径：followup（单调用 `FollowupAgent`）、custom（新 `QuestionPipeline`）、mimic（先经 `mimic_source.parse_exam_paper_to_templates` 解析 PDF/已解析目录得到 `QuizTemplate` 列表，再走 pipeline 的 `templates_override` 跳过 Explore/Plan）。

核心编排位于 `pipeline.py` 的 `QuestionPipeline`，严格划分为三个阶段：Phase 1 Explore（`run_agentic_loop` + THINK/TOOL/FINISH 协议，带 tool_summarizer 压缩工具结果）、Phase 2 Plan（单次 PLAN 标签步骤产出 JSON 模板列表）、Phase 3 Quiz（对每个 template 再跑一次 agentic loop 产出最终 `QuizPair`，失败时触发 `_repair_quiz_payload` 修复重试）。每阶段通过 `StreamBus.stage` 与 `emit_capability_result` 暴露 trace/stream 事件。

`coordinator.py` 提供 `AgentCoordinator` 兼容层，把旧 WebSocket 路由和 `tools.question.exam_mimic` 适配到新 pipeline；`__init__.py` 用 `__getattr__` 延迟导入以减轻 LLM 依赖的冷启动成本。

辅助子模块职责清晰：`history.py` 从 SQLite session store 加载历史答题记录供 Explore 避免重复；`request_config.py` 将 `main.yaml` 中的 `capabilities.deep_question.exploring` 配置映射为 pipeline runtime config；`agents/followup_agent.py` 继承 `BaseAgent` 处理单题 follow-up；提示词集中在 `prompts/{en,zh}/` 下按 agent_name 组织（`pipeline.yaml`、`deep_question.yaml`、`idea_agent.yaml`、`followup_agent.yaml`），由 `get_prompt_manager().load_prompts(module_name="question", ...)` 加载。
