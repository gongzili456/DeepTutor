模块以 `capability.py` 中的 `DeepResearchCapability` 为对外入口，仅负责请求校验与 outline-preview 两阶段交互；核心编排集中在 `pipeline.py` 的 `ResearchPipeline` 类，按四个阶段驱动 LLM：Phase1 (rephrase, 仅 `ask_user`)、Phase2 (decompose, 一次性 OUTLINE)、Phase3 (per-block 研究循环, THINK/TOOL/APPEND/FINISH + 动态队列调度)、Phase4 (reporting, OUTLINE→INTRO→SECTION→CONCLUSION 顺序步骤)。

- 数据层 (`data_structures.py`)：`TopicBlock` / `ToolTrace` / `DynamicTopicQueue` 提供可序列化、模糊去重、状态机 (PENDING/RESEARCHING/COMPLETED/FAILED) 的研究单元与队列。
- 引用子系统 (`utils/citation_manager.py`)：`CitationManager` 维护跨阶段的 citation ID (PLAN-XX / CIT-X-XX)，持久化到任务工作区，并解析 rag/web_search/paper_search 等工具返回的结构化来源。
- 配置与策略层：`request_config.py` 用 Pydantic 校验前端传入的 `{mode, depth, manual_subtopics, ...}`，映射为 `planning/researching/reporting/queue` 四段 runtime config；`mode_strategy.py` 定义 notes/report/comparison/learning_path 四种模式的策略表，集中控制是否启用 rephrase、decompose 模式、单遍阈值、引用开关等。
- 提示词：`prompts/en/pipeline.yaml` 与 `prompts/zh/pipeline.yaml` 通过 `get_prompt_manager().load_prompts('research', 'pipeline', language)` 加载，按 `labels/empty/system/notices/protocol/rephase/decompose/research_step/note` 等键组织，支持 `{placeholder}` 渲染。
- 依赖方向：capability → pipeline → data_structures/utils；pipeline 向上依赖 `deeptutor.runtime.agentic` 的 `run_agentic_loop` / `run_labeled_step` / `LabelProtocol` 抽象，向下依赖 `services.config` / `services.prompt` / `services.llm` 等基础设施，不反向依赖上层 capability。
