模块以 `capability.py` 中的 `VisualizeCapability(TurnCapability)` 为入口，根据 `render_mode` 分流两条路径：
- 文本型可视化（svg/chartjs/mermaid/mindmap/html）：调用共享的 `AgenticChatPipeline`，由 `VisualizationLoopCapability` 在 chat loop 内完成 generation/retrieval/repair/tool dispatch，最终通过 `submit_visualization` tool 提交到 canvas。
- Manim 路径（manim_video/manim_image）：走独立的 `_run_manim_path`，依赖可选的 `renderer-manim` 模块并复用 `MathAnimatorPipeline` 的分析→设计→代码→渲染→总结五阶段。

内部按职责分层：
- `agents/` 下三个独立 Agent（`AnalysisAgent`、`CodeGeneratorAgent`、`ReviewAgent`），均继承 `BaseAgent`，通过 `get_prompt` 加载 `prompts/{en,zh}/` 下的 YAML 提示词，负责单阶段 LLM 交互。
- `pipeline.py` 的 `VisualizePipeline` 是面向外部（如 Math Animator 子流程）编排这三个 Agent 的协调器。
- `models.py` 用 Pydantic 定义 `VisualizationAnalysis` / `ReviewResult`，并通过 `model_validator` 对 LLM 返回的枚举值做降级而非抛错。
- `utils.py` 提供本地确定性校验（`validate_visualization`）、HTML/SVG/Mermaid 提取与回退 HTML 生成。
- 顶层 `__init__.py` 仅暴露 `VisualizePipeline`，对外契约稳定；能力注册通过 `builtin_capability_manifest("visualize")` 声明。

依赖方向单向向外：capability → pipeline → agents → prompts/models/utils，不反向引用上层框架。
