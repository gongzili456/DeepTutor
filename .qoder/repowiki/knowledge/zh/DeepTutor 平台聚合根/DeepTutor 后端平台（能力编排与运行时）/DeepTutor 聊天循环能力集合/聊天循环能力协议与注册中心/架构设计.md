模块由三层构成：
- 协议层（protocol.py）：通过 `LoopExtension` Protocol 声明可选钩子（`is_active`、`system_block`、`augment_kwargs`、`pre_loop_seed`、`pre_loop`、`on_user_pause/resume`、`finish_instruction`、`settlement_recovery`、`tool_round_output_policy`、`final_text_override`），以及 `KnowledgeCapability` 基类以标记独占工具面；同时导出 `PromptBlock`、`END_LOOP`/`AGENT_OUTPUT`/`EVENT_METADATA` 等旧版 completion key。
- 注册层（registry.py）：从 `deeptutor.modules.catalog.manifests()` 解析 `loops` 清单生成 `LoopCapabilitySpec`，并通过 `load_entry_point_group` 从 `deeptutor.extensions`（主入口）和 `deeptutor.loop_capabilities`（兼容组）加载外部插件；`_coerce_loop_factory` 统一接受 class / factory / instance 三种形态，校验 `name`、`owned_tools`、`is_active` 后返回 `(instance, factory)` 对；`all_loop_capabilities` 按 turn 缓存于 `context.runtime.loop_extensions` 并写入 `capability_catalog`，`active_loop_capabilities` 再按 `is_active` 过滤。
- 包门面（__init__.py）：仅暴露 protocol 类型与 registry 中的公开符号，使用 `__getattr__` 惰性导入 registry，避免在纯协议消费方触发模块级 import。
依赖方向单向：registry → protocol → core.context；capabilities 子包只依赖本模块的协议与 catalog，不反向引用具体实现。
