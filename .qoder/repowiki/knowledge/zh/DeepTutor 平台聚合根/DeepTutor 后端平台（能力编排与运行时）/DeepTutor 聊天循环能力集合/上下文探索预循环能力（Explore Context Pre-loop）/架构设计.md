模块以 `capability.py` 中的 `ExploreContextCapability` 作为标准 Capability 入口，实现 `is_active` / `system_block` / `pre_loop` 等钩子；其核心逻辑延迟导入 `explorer.ContextExplorer` 以避免与 LLM 配置栈形成循环依赖。

内部三层划分：
- `capability.py`：注册为名为 `explore_context` 的能力，仅通过 `pre_loop` 钩子生效，不挂载任何 answer-loop 工具；负责检测 `source_index`、加载本地化 prompt YAML、构造 `PromptBlock("explore_context", ...)` 注入结果。
- `explorer.py`：`ContextExplorer` 是实际执行器，维护两条路径——优先走 `_run_loop`（基于 OpenAI tool-calling 的 bounded agentic 循环，最多 `MAX_LOOP_ROUNDS=5` 轮，最后强制无工具结束），失败或非原生 provider 时回退到 `_single_pass`（一次性 dump 源文本 + brief）；同时提供 `_investigate_native` 分支，当运行于 `DEEPTUTOR_CHAT_ENGINE=typescript-native` 且兼容层拒绝 Python 内置 `read_source` 时委派给 TS 引擎。
- `native.py`：面向 TypeScript 引擎的薄适配层，将 Python 侧的 source/prompt/budget 打包成 `InvestigationPort` 事件桥，把 CONTENT 事件重映射为 THINKING，确保调查结果永远进入 thinking trace 而非用户内容通道。

Prompt 资源位于 `prompts/en/` 与 `prompts/zh/` 下的 `explore_context.yaml`，由 `_load_prompts` 按语言缓存；预算（`loop.max_tokens`、`briefing.max_tokens`）从 `agents.yaml` 的 `capabilities.explore_context` 段动态读取。追踪统一使用 `EXPLORE_STAGE="context_exploration"` 与 `call_kind="context_exploration"`，供前端 TracePanels 渲染“Exploring your context…”状态。
