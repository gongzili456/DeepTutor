- 路由通过 `Depends(usable_partner)` / `Depends(manageable_partner)` 声明式校验资源存在性与调用者权限，而非在每个 handler 内重复判断。
- 请求体统一用 Pydantic `BaseModel` 描述（如 `CreatePartnerRequest`、`ImportedSession`），并通过自定义 `field_validator` / 顶层 `_validate_*` 函数在 API 边界做业务校验并抛出 `HTTPException(status_code=422)`。
- 对下游服务的访问一律通过 `get_*` 工厂函数（`get_partner_manager`、`get_sqlite_session_store`、`get_application_container`）获取，避免直接 import 单例。
- 跨进程后台任务通过 `_request_partner_control` 提交 `BackgroundCommandKind` 并轮询 `runtime_status_repository`，返回 `None` 表示本地执行，否则等待 leader 写入状态。
- 敏感字段（channel secrets、avatar base64、LLM selection）在构造 `PartnerConfig` 前后分别经 `mask_channel_secrets` / `_validate_avatar_payload` / `_validate_llm_selection_payload` 处理，确保序列化输出脱敏。
