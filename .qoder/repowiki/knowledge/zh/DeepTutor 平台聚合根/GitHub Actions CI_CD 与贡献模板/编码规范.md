- 每个工作流在顶层声明 `concurrency.group = ${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}` 并设置 `cancel-in-progress: true`，使同一 PR/分支 的新提交取消旧运行。
- 触发条件使用 `on.push.paths` / `on.pull_request.paths` 精确限定变更路径，避免无关工作流被触发。
- 发布类工作流（`pypi-release.yml`、`docker-release.yml`、`desktop-release.yml`）均先执行 `validate-release-tag` job，用正则校验 `vX.Y.Z[+metadata]` 格式后再进入构建阶段。
- 跨平台矩阵通过 `strategy.matrix.include` 显式声明 runner 与 target，而非隐式 OS 矩阵，便于对 macOS ARM/Intel/Windows 分别控制。
- 所有 `actions/checkout` 统一使用 `@v4`，Python/Node 工具链使用 `actions/setup-python@v5` / `actions/setup-node@v4`，保持 action 版本收敛。
- PR 模板与 `pull.yml` 共同约定：默认 base 分支为 `dev`，禁止直接提 PR 到 `main`，并通过 label `:arrow_heading_down: pull` 标记自动拉取的分支。
