- 对可选依赖 `graphrag` 采用延迟 import（函数体内 `from graphrag.* import ...`）配合 `is_graphrag_available()` 检查，使模块在无 extra 时仍可被正常导入。
- 通过生成 `settings.yaml` 而非构造 Pydantic 配置对象来对接 GraphRAG，仅填充 completion/embedding model、input/output/storage/cache/vector_store 等必要字段，其余走 GraphRAG 默认值。
- 每个 KB 使用 `index_versioning` 管理的 `version-N` 自包含目录作为 GraphRAG 项目根，并以 `meta.json` 作为“已就绪”标记，由 `storage.write_meta` 统一写入。
- 检索错误与缺失索引场景统一收敛为带 `provider`、`error_type`、`needs_reindex` 字段的标准化响应字典，便于上层 UI 区分处理。
- 所有 GraphRAG 阻塞式 API 调用都经 `_run_isolated` 包装，在新 asyncio event loop 中以 `asyncio.to_thread` 执行，隔离 uvloop 与 nest_asyncio 冲突。
- 文件类型路由复用 `FileTypeRouter`，仅接受 parser 解析出的文本与纯 `.txt`，图片与不支持格式记录 warning 后跳过，保持 GraphRAG 纯文本输入契约。
