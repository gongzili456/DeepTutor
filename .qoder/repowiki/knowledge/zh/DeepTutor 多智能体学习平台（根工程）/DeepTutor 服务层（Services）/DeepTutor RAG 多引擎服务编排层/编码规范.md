- 新增 RAG 引擎需在 `factory.KNOWN_PROVIDERS` 注册常量并通过 `_build_pipeline` 分支延迟导入其 pipeline 类
- 每个管道目录遵循 `config.py` + `pipeline.py` + 可选 `storage.py`/`client.py`/`probe.py` 的结构，对外仅暴露 Pipeline 类
- Provider 名称一律经 `normalize_provider_name` 归一化为小写并校验于 `KNOWN_PROVIDERS`，未知值回退到默认引擎
- 管道返回结果统一包含 `query`/`answer` 或 `content`、`provider`、可选 `error_type`/`needs_reindex`，由 service 层在 search 中补齐
- KB 与 provider 的绑定关系只通过 `provider_binding` 读写 `kb_config.json`/`metadata.json`，禁止直接解析 JSON
- 可插拔依赖（如 PageIndex、GraphRAG、LightRAG）通过 try/except 探测可用性并在 `list_pipelines` 中暴露配置状态
