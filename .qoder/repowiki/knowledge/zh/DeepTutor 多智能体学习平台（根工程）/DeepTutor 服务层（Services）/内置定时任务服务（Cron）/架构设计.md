模块由三个文件组成清晰的两层结构：
- `service.py` 定义数据模型（`CronSchedule`、`CronOwner`、`CronJobState`、`CronRunRecord`、`CronJob`）与核心调度器 `CronService`，负责 JSON 持久化（`jobs.json`，原子写入 + 损坏备份）、作业增删查、按 `next_run_at_ms` 轮询的 asyncio 事件循环（通过 `_wake` Event 唤醒，最长每 60 秒重扫一次），以及 `compute_next_run`/`validate_schedule` 对 `at`/`every`/`cron` 三种调度类型的计算与时区校验。
- `executor.py` 实现 `execute_job`，根据 `owner.kind` 分派到 `_execute_chat_job`（在用户上下文中调用 `ChatOrchestrator` 并追加消息到 SQLite 会话）或 `_execute_partner_job`（通过伙伴总线注入 `InboundMessage`，非流式结果再经 `OutboundMessage` 回发），并提供可选的 macOS 桌面通知（`osascript`）。
- `__init__.py` 仅做公共 API 重导出；`get_cron_service()` 作为进程级单例懒加载，将持久化路径锚定在 admin workspace 下的 `cron/jobs.json`，并将 `executor.execute_job` 注入为 `on_job` 回调。
依赖方向单向：`executor → service`，`service` 仅在 `start/get_cron_service` 中按需 import 其他子系统（multi_user、partners、session、orchestrator），避免启动期循环导入。
