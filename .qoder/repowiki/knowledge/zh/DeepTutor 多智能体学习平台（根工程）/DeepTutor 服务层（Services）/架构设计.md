本模块以 `config`（YAML/JSON 运行时设置与模型目录）、`auth`（JWT/用户认证）、`path_service`（数据目录）和 `provider_registry`（LLM Provider 注册路由）作为跨子模块共享的基础设施；各业务子模块（llm、rag、memory、session、search、sandbox、subagent、partners、mcp、embedding、parsing、voice、imagegen、videogen、cron、skill、persona、prompt、codex_auth、model_selection、cli_apps、notebook、storage、setup）均遵循同一契约：对外暴露一个 Service/Client 门面类，内部按 adapters/providers 子目录实现多后端可插拔，并通过 config 中的 YAML 配置在启动时动态装配。上层调用方（如 agent 或 CLI）不直接依赖具体后端，而是通过 session.turn_runtime 或 llm.client 等统一入口发起请求，由各自模块内部的 factory/provider_factory 根据当前上下文（KB、模型选择、Partner scope）路由到对应实现。跨模块协作的典型链路包括：session 回合 → memory 持久化 → rag/smart_retriever → embedding/search → llm 调用 → sandbox 执行工具 → cron 定时投递，所有环节共享同一份 config 单例与 auth 上下文。
