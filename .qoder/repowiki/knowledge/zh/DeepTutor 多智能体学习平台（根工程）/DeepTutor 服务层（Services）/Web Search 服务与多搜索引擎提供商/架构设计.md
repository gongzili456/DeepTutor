模块采用「统一接口 + 插件式提供商」架构：
- `base.py` 定义抽象基类 `BaseSearchProvider`，规定 `search(query, **kwargs) -> WebSearchResponse` 契约及 `requires_api_key`、`supports_answer`、`BASE_URL`、`API_KEY_ENV_VARS` 等元数据；所有具体提供商继承该类。
- `providers/` 下每个搜索引擎一个文件（duckduckgo、brave、tavily、jina、perplexity、serper、searxng、baidu、exa、openrouter），通过 `@register_provider(name)` 装饰器在模块导入时注册到全局 `_PROVIDERS` 字典；`providers/__init__.py` 集中加载内置提供商并提供 `get_provider`、`list_providers`、`get_available_providers`、`get_default_provider` 等工厂方法，并将 exa/baidu/openrouter 标记为已弃用不可用。
- `types.py` 定义跨提供商共享的数据模型 `Citation`、`SearchResult`、`WebSearchResponse`（含 `to_dict()` 向后兼容序列化）。
- `consolidation.py` 提供 `AnswerConsolidator`，对 `supports_answer=False` 的原始 SERP 提供商执行答案生成：优先使用 Jinja2 模板（`PROVIDER_TEMPLATES` 中为 serper/jina/serper_scholar 定制，否则回退到通用格式），或可选调用 `deeptutor.services.llm.get_llm_client` 进行 LLM 合成。
- `__init__.py` 暴露顶层 API `web_search()`，负责读取配置（`deeptutor.services.config.resolve_search_runtime_config`）、校验 provider、注入 api_key/proxy/max_results、调用具体 provider、按需触发 consolidation，并支持将结果持久化为 JSON 文件。
依赖方向单向：`__init__` → `providers` → `base` → `types`；`consolidation` 仅依赖 `types` 和外部 LLM 客户端，不被 providers 引用。
