模块以 `service.py` 中的 `CodexOAuthService` 为编排中心，协调四个职责清晰的子组件：
- `oauth.py`：实现 PKCE 流程、构造授权 URL、通过 `httpx` 调用 `CODEX_TOKEN_URL`/`CODEX_REVOKE_URL`，并提供绑定在 `127.0.0.1`/`::1` 的 `LoopbackCallback` 异步 HTTP 服务器接收浏览器回调。
- `catalog.py`：`CodexModelCatalog` 使用 access token 调用 `CODEX_MODELS_URL`，按 account_hash + generation 缓存快照，支持 fresh/revalidated/stale 三级缓存与 ETag 协商。
- `storage.py`：`CodexCredentialStore` 将凭证、状态和目录缓存原子写入用户根下的 `private/openai-codex/*.v1.json`，通过文件锁 (`fcntl`/`msvcrt`) 与递增 `generation` 字段保证并发安全，并在首次使用时把旧位置迁移到不可被沙箱其他账户读取的 secrets 目录。
- `contracts.py`：定义 `CodexCredentials`、`CodexToken`、`CatalogSnapshot`、`CodexModel` 等不可变数据类及 `decode_codex_jwt`，所有外部输入经 `from_dict` 严格校验后抛出 `CodexAuthError`。
- `constants.py`：集中上游 Commit、Client Version、OAuth Issuer/Scope、端口、超时与安全上限等常量。
依赖方向单向：`service → oauth/catalog/storage`，三者仅依赖 `contracts` 与 `constants`；`__init__.py` 只暴露顶层 API。进程级单例 `_SERVICE_INSTANCES` 按 owner secrets root 键化，并通过 `deliver_codex_oauth_callback` 用 state 常量时间比较路由回调到正确的登录操作。
