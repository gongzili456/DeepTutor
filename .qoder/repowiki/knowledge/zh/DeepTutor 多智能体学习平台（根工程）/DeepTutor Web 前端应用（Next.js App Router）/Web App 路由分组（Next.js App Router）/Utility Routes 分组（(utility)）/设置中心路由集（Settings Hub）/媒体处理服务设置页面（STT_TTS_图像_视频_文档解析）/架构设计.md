该模块基于 Next.js App Router 的 `(utility)/settings` 路由组，每个子目录对应一个独立的 `page.tsx` 客户端组件：
- STT、TTS、Image、Video 四个页面结构高度一致：使用 `SettingsPageHeader` 展示标题与说明，再嵌入通用的 `ServiceConfigEditor service="..."` 组件来渲染对应服务的键值配置表单，由上层 settings 共享逻辑负责保存。
- TTS 页面额外组合了 `useVoiceAutoplayPreference` Hook 实现“自动播放回复”开关，作为服务配置之外的独立偏好项。
- Document Parsing 页面是例外，不依赖 `ServiceConfigEditor`，而是自管状态并通过 `apiFetch(apiUrl(...))` 直接调用 `/api/v1/settings/document-parsing` REST 接口，按当前选中的 engine（text_only / mineru / docling / markitdown / pymupdf4llm）条件渲染对应的 Panel 组件；可选包未安装时显示 `NotInstalledSection`，通过 `useBackgroundJob` Hook 启动 pip install 或模型下载后台任务，并以 cursor 分页轮询 `/job/status` 流式拉取日志。
- MinerU 页面仅保留为兼容旧书签的重定向页，将请求重定向到新的 document-parsing 路由。
依赖方向单向向下：页面 → 共享 settings UI 组件（`SettingsPageHeader`、`SettingRow`、`Toggle`）→ 通用 `ServiceConfigEditor` 或自定义 API 调用，不反向依赖业务逻辑。
