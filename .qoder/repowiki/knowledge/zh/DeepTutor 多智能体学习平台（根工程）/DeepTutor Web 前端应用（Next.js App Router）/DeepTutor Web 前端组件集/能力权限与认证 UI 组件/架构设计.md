模块按职责分为两个子目录：
- `components/access/` 实现能力（Capability）级别的访问控制，采用 React Context + Provider 模式：`CapabilityAccessContext.tsx` 通过 `apiFetch('/api/v1/settings')` 探测是否拥有 catalog 字段来判断管理员身份，并对非管理员调用 `listLLMOptions` 判断是否有可用 LLM；默认值使组件在 provider 外部渲染时乐观放行，后端仍是最终执行边界；同时监听 `focus` 与 `visibilitychange` 事件以在会话中重新探测授权变更。
- `CapabilityGate.tsx` 作为路由级门控，基于当前 pathname 经 `capabilityForPath` 推导所需 Capability，再委托给 `RequireCapability`；`RequireCapability.tsx` 根据 `useCapabilityAccess().has()` 决定是否渲染 `LockedFeatureNotice`（带锁图标与 i18n 提示）或子节点。
- `components/auth/` 为纯展示型导航组件：`AdminLink`、`LogoutButton`、`ProfileLink` 均通过 `@/hooks/useAuthStatus` 读取认证状态，仅在 `enabled` 且满足条件时渲染，并支持 `collapsed` 属性切换紧凑/展开两种样式。
依赖方向单向向下：access 层不依赖 auth 层，auth 层仅依赖 `@/hooks/useAuthStatus` 与 `@/lib/auth`，两者共同依赖 Next.js Router、i18next 与 lucide-react 图标。
