模块以 `capability.py` 中的 `ExploreContextCapability` 作为能力入口，实现 `LoopCapability` 协议：通过 `is_active` 检测 `context.metadata['source_index']` 非空来激活，并通过 `pre_loop` 钩子注入一个 `PromptBlock('explore_context', ...)` 到答案循环的用户消息种子中；它不注册任何 answer-loop 工具，也不输出 system block。

核心调查逻辑集中在 `explorer.py` 的 `ContextExplorer` 类，提供两条执行路径：
- 主路径 `_run_loop`：使用原生 tool calling，构建 `read_source` 的工具 schema（枚举限制为当前 source_index 的 id），在最多 `MAX_LOOP_ROUNDS=5` 轮内交替调用 LLM 与 `dispatch_tool_calls`，直到模型停止调用工具并写出调查报告；最后一轮禁用 tools 强制结束。
- 回退路径 `_single_pass`：当 provider 不支持原生 tool calling 或主路径失败时，将截断后的源文本直接拼入 prompt 进行一次单遍 brief。

提示词通过 `prompts/en/` 与 `prompts/zh/` 下的 YAML 文件按语言加载，并使用 `_PROMPT_CACHE` 缓存；所有用户可见文案通过 `_t(key)` 从 prompts 字典中解析，支持嵌套 key（如 `loop.system`、`status.exploring`）。

依赖方向单向向外：仅依赖 `deeptutor.core.agentic`、`core.context`、`core.stream_bus`、`services.llm`、`runtime.registry.tool_registry`，不被答案循环反向引用，从而避免循环导入——`explorer` 在 `pre_loop` 时才被延迟 import。

前端通过 `EXPLORE_STAGE='context_exploration'` 与 `call_kind='context_exploration'` 在 trace 中标记该阶段，用于显示“Exploring your context…”状态。
