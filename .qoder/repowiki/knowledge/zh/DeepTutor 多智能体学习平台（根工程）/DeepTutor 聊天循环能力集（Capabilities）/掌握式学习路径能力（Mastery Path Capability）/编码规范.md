- 工具类统一继承 `BaseTool`，通过 `get_definition()` 返回 `ToolDefinition` 描述参数，并在 `execute` 开头用 `_resolve_path_id` 校验路径是否激活，未激活时返回统一的 `_no_path_result()`。
- 对 `learning.service` / `storage` / `scheduler` 等可能引发循环引用的依赖采用函数内懒导入（`_new_service`、`_sync_mastery_attempt_to_question_bank` 等），仅在调用时 import。
- 所有对外暴露的工具名集中在 `MASTERY_TOOL_NAMES` 元组中声明，capability manifest、loop hook 的 `owned_tools`、pipeline mount 策略都引用该单一来源，避免注册表与挂载列表不一致。
- 工具返回值统一通过 `_json_result(payload, meta_key=...)` 构造 `ToolResult`，将结构化 payload 同时放入 `content`（JSON 字符串）与 `metadata`（字典）。
- 路径标识符一律经 `_sanitize_path_id` 清理后再用作存储 key，确保与 `LearningStore` 的路径守卫兼容。
- 选择题数据契约集中在 `choices.py` 的纯函数中（`parse_options` / `format_options` / `resolve_answer` / `has_option_bodies`），工具层只调用这些函数而不直接操作原始字符串。
