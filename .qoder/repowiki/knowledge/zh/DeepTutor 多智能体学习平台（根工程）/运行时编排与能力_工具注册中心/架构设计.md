模块以 `orchestrator.ChatOrchestrator` 为统一入口，接收 `UnifiedContext` 后通过 `CapabilityRegistry` 查找并调用对应 capability（默认 `chat`），使用 `StreamBus` 流式回传事件并在完成时发布 `CAPABILITY_COMPLETE` 事件。

- 注册中心层：`registry/capability_registry.py` 与 `registry/tool_registry.py` 分别维护能力与工具的单例，启动时从 `bootstrap/builtin_capabilities.py` 中的类路径动态 import 内置能力，并通过可选的 `deeptutor.plugins.loader` 钩子加载插件；工具还支持别名解析与 OpenAI schema 生成。
- 提供者安全层：`providers/` 位于注册中心之下，按 `allowlist → scope → authorize → text` 自底向上分层，对 MCP 等外部来源的工具进行名称白名单、作用域授权与提示文本清洗，`view` 单独组合 registry 暴露给上层。
- 运行模式与环境：`mode.py` 通过 `DEEPTUTOR_MODE` 环境变量在 CLI/SERVER 间切换；`home.py`、`banner.py` 提供运行时目录与多语言横幅；`request_contracts.py` 用 Pydantic 模型集中校验各能力的公开配置，剥离 `_RUNTIME_ONLY_KEYS` 后再下发。
- 进程编排：`launcher.py` 负责 `start` 命令，探测并复用已运行的 Next.js 前端，构建或复制 packaged web 资源，处理端口冲突、信号转发与优雅关停；`memory_reclaim.py` 在 Linux 上通过 `malloc_trim` 释放大作业后的堆内存。
依赖方向自上而下：orchestrator → registry/providers → core/agents/tools；launcher/home/banner 仅作为进程外壳不反向依赖编排逻辑。
