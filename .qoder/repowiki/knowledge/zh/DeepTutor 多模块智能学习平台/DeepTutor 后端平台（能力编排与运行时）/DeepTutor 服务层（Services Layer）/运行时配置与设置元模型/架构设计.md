模块以 `__init__.py` 作为对外门面，通过 `importlib` + `__getattr__` 惰性导入 `provider_runtime`、`knowledge_base_config`、`test_runner` 等重依赖子模块，避免在 `deeptutor.capabilities` 导入时产生循环依赖。

内部按职责分层：
- 基础加载层：`loader.py` 定义 `PROJECT_ROOT`（指向 `data/user/settings`）、YAML 深合并、路径注入（`_inject_runtime_paths`）和 `agents.yaml` 的 per-capability LLM 预算读取；`launch_settings.py`、`settings_profile.py`、`settings_presets.py`、`settings_spec.py`、`settings_draft.py` 围绕 `SettingSpec` 数据类描述可写设置项（area/scope/effect/probe）。
- 持久化服务层：`runtime_settings.py` 维护 system/auth/integrations/document_parsing 等多份 JSON 配置的默认值、迁移逻辑与读写 API；`model_catalog.py` 提供 `ModelCatalogService`，负责 `model_catalog.json` 中 connections/services/profiles 的 CRUD、凭据脱敏（`CATALOG_SECRET_MASK`）与还原。
- 运行时解析层：`provider_runtime.py` 将 catalog 中的 profile 解析为 `ResolvedLLMConfig`/`ResolvedEmbeddingConfig`/`ResolvedSearchConfig`，并集中声明 `SEARCH_PROVIDERS`、`EMBEDDING_PROVIDERS`、`NANOBOT_LLM_PROVIDERS` 等提供者表；`embedding_endpoint.py`、`provider_links.py`、`origins.py`、`image_description.py` 提供领域归一化工具。
- 能力扩展层：`capabilities_settings.py`、`context_window_detection.py`、`lightrag_roles.py`、`knowledge_base_config.py`、`readiness.py`、`test_runner.py` 分别暴露各子系统所需的配置访问器。

依赖方向单向向外：本模块被 `deeptutor.capabilities.setup`、`deeptutor.services.llm`、`deeptutor.services.embedding` 等上层消费，自身仅反向通过延迟 import 访问它们以避免环。
