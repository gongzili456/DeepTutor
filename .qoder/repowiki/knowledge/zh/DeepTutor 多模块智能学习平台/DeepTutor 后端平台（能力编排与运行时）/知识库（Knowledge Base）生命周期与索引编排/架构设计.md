模块以 `manager.py` 中的 `KnowledgeBaseManager` 为中央协调者，负责持久化 `kb_config.json`、发现/自动注册 KB、清理孤儿条目、同步 PocketBase，并通过 `update_kb_status` 统一维护状态机（initializing → processing → ready/error）。

- 领域入口：`__init__.py` 通过 `__getattr__` 实现延迟加载，仅导出 `DocumentAdder`、`KnowledgeBaseInitializer`、`KnowledgeBaseManager`。
- 初始化流程：`initializer.py` 创建 `<kb>/raw` 目录结构，调用 `RAGService.initialize` 完成首次索引；`indexing_run.py` 提供跨进程/可恢复的 `.indexing-run.json` 日志与 `.indexing.lock` 独占锁，支持中断恢复与取消。
- 增量添加：`add_documents.py` 的 `DocumentAdder` 复用 `staging.stage_source` 将文件落盘到 `raw/`，按 provider 走 LlamaIndex 批量 publish、LightRAG 快照发布或逐文件回退路径，并在 `metadata.json` 中记录 `file_hashes` 做去重。
- 共享基础设施：`staging.py` 提供内容哈希与防覆盖拷贝；`progress_tracker.py` 把进度写入 `.progress.json` 并通过 `progress_events.py` 的端口接口广播给 WebSocket/task-stream；`manifest.py` 从磁盘扫描 `raw/` 构建 `KbManifest`，对 connected KB 通过 `_REMOTE_INVENTORY_READERS` 插件式读取远端列表；`kb_types.py` 集中声明所有 KB 类型常量及 `is_connected_kb` / `external_root_of` 等判别函数，被 manager 与 manifest 共同依赖以避免循环；`naming.py` 提供名称校验。
- 扩展点：`module_service.py` 暴露 `start_github_sync` / `stop_github_sync` / `start_web_source_sync` / `stop_web_source_sync` 作为已安装模块贡献的后台服务钩子。

依赖方向：本模块向上依赖 `deeptutor.services.rag.*`（provider 抽象）、`deeptutor.services.file_io`（原子写）、`deeptutor.services.parsing.progress`（解析进度），向下不反向依赖上层 capability 层，仅通过 `kb_types.py` 的类型常量与 `progress_events.py` 的端口回调解耦。
